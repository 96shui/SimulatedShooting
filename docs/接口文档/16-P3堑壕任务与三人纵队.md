# 16 P3 堑壕任务与三人纵队（task007）

2026-09-14，v1.2技术候选，补充接口07/08/14/15。独立审核与真实关卡装配另行记录。

## 任务与批次

TrenchService实现ITrenchService、ICombatWorldInputPort、ICombatStateService、IHUDService、IDisposable；新增Advance(sessionId)作为任务批次结束入口。构造注入CombatSceneDefinitionDto、ICombatClock、ICombatRandom、ICombatNavigationPort、可选CombatConfigDto及SessionId工厂。Combat属性暴露ICombatCoreService用于武器输入；核心由任务拥有，Dispose一并释放。

只提供trench-a，武器只允许training-rifle；未提供武器InvalidState，未知地图/武器NotFound。地图校验失败沿用InvalidInput/ResourceUnavailable。简报仅生成计划DTO，不创建会话、不运行随机或导航。StartSession才随机选3–5名敌人：按PointId排序，先取数量NextInt(3,6)，再无放回抽候选点；SeededCombatRandom提供稳定xorshift序列，Unfixed的实际Value由调用者提供，服务不暗取系统随机。稳定实体ID以新SessionId为前缀。运行中重复Start为Busy；终局/Cancel后可开始新局，禁止复用旧ID。

场景先提交本Tick全部事实，再调用TrenchService.Advance：战斗核心处理伤害与击杀→任务登记搜索/死亡→更新队伍→统一评估结果→发布完整快照。UI不能调用击杀登记使活敌死亡。RegisterEnemyKilled仅确认核心已死亡的已知实体；FailByPlayerDeath仅在核心已死亡时有效。CompleteIfReady/手工登记不能越过尚未处理的事实队列（Busy）。新增CombatCoreService.HasPendingInputs供任务边界校验，不改变ICombatCoreService接口。

AreaPresence.EntityId为节点ID、Flag为范围内；Tick必须为当前批次。进入范围自动完成节点，任意顺序、一次计数。MarkSearchNode对已完成节点幂等，否则范围外InvalidState。空参数InvalidInput，未知ID/旧会话NotFound。同EventId同载荷幂等、不同载荷InvalidInput。NavigationResult的TargetId关联导航RequestId，Position是实际位置，Direction是实际朝向，Flag表示成功；不把提交导航请求当作已移动。

胜利要求节点全完成、敌人全死、玩家存活。核心死亡优先失败，同批次已完成搜索/击杀保留。结果一次生成并不可变；终局命令重试返回原结果，非法/旧会话不能改结果。Cancel本局幂等、不生成新结果，已有结果可查询直到新局。重试流程Cancel→GetBriefing→StartSession，保留地图与武器参数，清空节点、计数、队伍、计时、输入和结果；旧会话不再可查询。

用时按ICombatClock的逻辑时间，Running且跟踪有效时累计，暂停/跟踪中断/终局停止；大批次以该批次结束时间记结算，不推测真实帧内时刻。终局禁止再推进导航。CombatCoreSnapshotDto新增TrackingValid只读数据字段，避免把未持枪误判为跟踪丢失。

## 三人纵队

SquadFormationService可供城镇复用，实现ISquadCommandService与ICombatWorldInputPort，公开Start、UpdatePlayer、GetVisualSnapshot、Stop、Changed、NavigationFailed。只读SquadStatusDto含玩家及两名队友，空命令列表、CommandMenuAvailable=false；Issue/OnReloadStarted为InvalidState。

记录玩家真实已走折线，二号目标在路径后1.5m并沿路径朝前，三号后3m并沿路径朝后；初始路径由出生点朝后延长3m。目标是沿路径回溯而非直线穿角，输出导航请求不修改玩家。路径历史按最大落后距离裁剪，失败队友可由导航适配器重新寻路到当前队形目标。

导航请求成功表示已接收；位置仅由匹配RequestId的成功NavigationResult更新。请求失败或到达失败时保持原位置、HoldingPosition并发NavigationFailed，1秒后可重试；请求无响应在1秒后视为超时，进入下一次1秒重试等待。暂停/失踪清空待到达请求，迟到回调InvalidState；恢复从当前位置重新寻路。队形朝向在视觉DTO的Forward里，SquadMemberDto沿用已有结构。玩家及队友存活数值来自核心/固定基础队员配置，不做队友战损和战术动作。

## HUD、地图和事件

任务SessionChanged/ResultReady、HudUpdated及PlayerChanged/SquadChanged/VisualChanged在发布前先更新所有查询快照；可安全读取同一Revision。写命令在回调中重入为Busy。服务订阅核心一次，释放时退订，不按每次重试增加订阅。

HUD包含弹药、玩家姿态/生命、CanShoot、搜索/敌人数/计时和队伍状态。地图坐标用场景投影矩形归一化并限幅；简报/HUD只有敌情预估中心，死亡叉号也用预估中心，不泄漏随机实际偏移。真实生成/尸体位置仅通过场景视觉查询暴露。搜索节点用Objective/SearchedRoom标记且已完成区域用信息色标记，Presenter选择具体颜色。公开列表只读，后续局不能改动旧结果列表。

地图预览/开始/返回页面导航、摘要保存和真实场景装配由task013负责；本任务不新增页面。对接方法与无VR自动化路径在交付记录中列出。

# 20 模式三无人机开场侦察契约

2026-10-03 新增规格；对应 BDD14/28，P3 玩法 task016、场景 task017、UI task018。以下接口与类型为待实现契约候选，需在接入前交付可编译定义和三线替身并补充节点 A 签核。本次文档更新不代表已有代码支持。

## 生命周期与责任

仅 `TrainingMode.Trench` 启用。简报预览不创建角色、不播放起飞。应用 `Start` 创建 `Preparing` 会话及同种子角色，先应用全员行为锁，再激活可见角色及无人机；不能先激活一帧战斗再补锁。

`Preparing` 下的子阶段依次为 `PlayerTakeoff → DroneRecon → DroneReturn → DroneLanding → RestoringPlayerView`。无人机落地和玩家视角恢复均确认后进入 `Ready`，应用协调层同一事务执行 `BeginCombat`，发布 `Running` 快照并解除全员行为锁，开战事件只发布一次。无人机和人物不共用冻结时钟；准备阶段可推进开场，但不能调用战斗 Tick 推进攻击、导航、搜索或用时。

准备创建事件/快照与正式开战事件区分：监听方不得把“会话已创建”当作可战斗。既有 `SessionStartedEvent` 的正式开战语义在本扩展中只随Running发布，Preparing通过准备/开场快照通知；task016同步更新原订阅方和测试。

UI 只发原有应用开始/返回命令，不发航线完成或 `BeginCombat`。场景只报告带会话与步骤标识的事实，不决定是否开战。玩法服务校验顺序，应用层协调视频、玩家视角及正式开战。

## 新增类型与查询事件

```csharp
public enum DroneReconPhase
{
    NotStarted, PlayerTakeoff, DroneRecon, DroneReturn,
    DroneLanding, RestoringPlayerView, Ready, Cancelled, Error
}
public enum DroneReconViewMode { Player, DroneFeed }

public readonly struct DroneReconSnapshotDto
{
    public string SessionId { get; init; }
    public long Revision { get; init; }
    public string SequenceId { get; init; }
    public string StepId { get; init; }
    public DroneReconPhase Phase { get; init; }
    public DroneReconViewMode ViewMode { get; init; }
    public bool CharacterActionsLocked { get; init; }
    public bool FeedAvailable { get; init; }
    public string FeedBindingId { get; init; }
    public float ReconElapsedSeconds { get; init; }
    public bool TelemetryValid { get; init; }
    public float HeightAboveGroundMeters { get; init; }
    public float SpeedMetersPerSecond { get; init; }
    public ErrorCode ErrorCode { get; init; }
}

public interface IDroneReconService
{
    ServiceResult<DroneReconSnapshotDto> Begin(string sessionId);
    ServiceResult<DroneReconSnapshotDto> GetSnapshot(string sessionId);
    ServiceResult<Unit> Advance(string sessionId);
    ServiceResult<Unit> Cancel(string sessionId);
    event Action<DroneReconSnapshotDto> Changed;
}
```

DTO 不包含 Camera/Transform/Texture。`FeedBindingId` 由 Unity 表现绑定端口解析当前租约的 RenderTexture，业务服务只查询可用性。遥测来自场景相机/无人机的实测反馈；无数据设 `TelemetryValid=false`。侦察用时独立累计，不写入结算 `ElapsedSeconds`。`Revision` 单调递增，事件发布前更新查询；回调重入写命令返回 Busy。

## 堑壕任务接口变化

`ITrenchService` 增加：

```csharp
ServiceResult<TrenchSessionDto> PrepareSession(string mapId, string weaponId, RandomSeed seed);
ServiceResult<TrenchSessionDto> BeginCombat(string sessionId);
```

`PrepareSession` 完成配置校验、同种子生成本局 3–5 敌人、两名队友及核心初始数据，返回 `Preparing`；不发送攻击/导航、不开始计时。既有 `StartSession` 保留签名并委托准备语义，生产入口及原来假定直接 Running 的 Fixture/测试均由 task016 更新。禁止通过旧方法绕过侦察。`BeginCombat` 只由拥有本局的应用协调层在开场 `Ready` 后调用；验证降落、视角恢复和当前序列，提前调用 `InvalidState`，已进入 Running 则幂等返回当前状态，不重生成敌人。

`TrenchSessionDto.State` 和核心查询状态必须同步 Preparing/Running；核心与任务业务入口统一校验准备门禁。人工伤害/导航/搜索事实在 Preparing 中拒绝，不缓存至开战。新输入门禁字段旧值默认锁定，不能因未绑定新组件默认放行。取消后准备数据清理不产生成败结果。

## 场景命令与事实端口

2026-10-03 工程定义已加入 `DroneReconContracts.cs`：场景端口以 `Prepare`、`PlayStep`、`SetCharacterActionsLocked`、`SetSuspended`、`RestorePlayerView`、`StopAndReset` 和 `FactReceived` 实现下表。暂停/跟踪门禁通过可注入的 suspended 查询协调，场景收到 SetSuspended 后暂停自身飞行动画和完成回调。独立状态机为 `DroneReconService`，尚未接入 TrenchService/生产装配。协调层在接受 BeginCombat 后调用该实现的 ConfirmCombatStarted，才释放场景行为锁；UI只接触查询/事件及原应用命令。

task016 在共享 Contracts 定义 `IDroneReconScenePort` 与值类型命令/事实；task017 实现 Unity 适配，task018 用独立视频绑定适配消费画面。端口必须包含：

| 方向 | 操作/事实 | 必需字段与语义 |
|---|---|---|
| 服务→场景 | Prepare/PlayStep | SessionId、SequenceId、StepId、Phase、RouteId、DurationSeconds；仅当前步骤执行，重复相同命令不重复播放 |
| 服务→场景 | SetCharacterActionsLocked | SessionId、锁定值；覆盖玩家/队友/敌人和所有武器/AI/手雷入口 |
| 服务→场景 | RestorePlayerView/StopAndReset | SessionId、SequenceId；恢复原玩家视角/出生姿态，停止航线、清理音源与视频，幂等 |
| 场景→服务 | StepCompleted | SessionId、SequenceId、StepId、Phase；起飞/航点/返航/降落/恢复分别确认，旧步骤不能推进当前状态 |
| 场景→服务 | FeedState/Telemetry | 相同关联ID、可用性、绑定键、实测高度/速度；视频画面不进入业务 DTO |
| 场景→服务 | StepFailed | 相同关联ID、ResourceUnavailable 与可读原因；保持门禁，恢复玩家观察方式 |

起飞结束要求可注入时钟达到默认 3 秒且起飞表现完成；之后切视频前还须确认输出就绪。侦察要求全部有序航点完成，返航要求回到出生处降落点，落地和玩家视角恢复分别确认，不用固定等待替代到达。每步有可配置正值超时，超时视作资源/表现失败；暂停或跟踪失效不累计逻辑时长或超时。

配置包括 RouteId/有序航点/起降锚点、TakeoffSeconds（默认3）、飞行速度、每步超时、视频资源键和滤镜配置键；位置/速度/时长须为有限合法值。敌人随机只在准备时执行一次；无人机不新增随机逻辑。

## 全员门禁

| 对象 | 正式开战前禁用 | 保留 |
|---|---|---|
| 玩家 | 拾枪及握持、开火、换弹、人工移动/转向、姿态/换肩战斗命令、区域交互、手雷请求 | 真实头手跟踪、返回/取消 UI |
| 队友 | 拿枪/射击/投掷动画、跟随导航、战术动作 | 冻结位置的待命表现 |
| 敌人 | 持枪战斗动作、感知攻击/导航、伤害/死亡处理 | 本局实体和可被无人机看见的外观 |
| 任务 | 搜索、击杀、胜负评估、战斗计时 | 开场状态/资源/取消事件 |

武器可以在出生处显示，准备阶段不可被 XR 或无 VR 握持。准备阶段 `CanShoot=false`；相关服务命令返回 InvalidState，场景事实适配同步拦截。解锁时清除待执行命令与旧输入边沿，握把、扳机、摇杆及投掷必须释放后重新输入；不能把开场点击扳机延迟为第一发子弹。

## 相机、监控 UI 与绑定

桌面观察输出切换到无人机 Camera 的实时视频；VR 使用稳定观察屏展示同一视频，保留 HMD 原生跟踪，不将无人机动画施加到 HMD/Interactor。恢复原玩家观察方式后才开战。主输出与音频 Listener 管理保持唯一，视频捕获相机独立输出 RenderTexture。

监控页面为新增 `ScreenId.TrenchDroneRecon`，沿用已有 `TrenchBriefingStart` 或等效开始事件；返回复用应用 Back/取消命令。无人机 UI 不新增跳过/开火按钮。LIVE、观察框、阶段、侦察用时及滤镜为必需；高度/速度为有数据才显示的遥测。视频滤镜不作用于玩家相机或全局环境；敌人标记仍来自既有敌情预估 DTO，不因滤镜自动暴露所有精确敌人坐标。不要求保存视频文件。

稳定对象/ID 见 task017/018；接口11同名约束适用。p14 保留简报地图布局，p28 定义监控观察布局。

## 生命周期与错误

- Begin 同局当前序列重复请求返回当前快照；开始按钮重复提交不创建第二局。另一次开场尚未清理时返回 Busy。
- 旧 SessionId 返回 NotFound；非法阶段、步骤乱序返回 InvalidState；非法配置返回 InvalidInput；资源/超时/视频失败返回 ResourceUnavailable。重复相同完成事实幂等，冲突载荷 InvalidInput。
- 错误时恢复玩家观察方式但保持本局门禁。重试开场清理旧 Preparing 会话后用新 ID 从头播放；正式战斗结果重试仍按接口18先回简报，再完整开场。
- 返回、切模式、加载取消、租约卸载、Dispose 必须停止飞行、释放视频资源和回调；迟到事实不能恢复旧相机或开战。相机恢复不能解除已取消会话的战斗门禁。
- task015 手雷仅在模式三 Running 生效，开场不推进投掷与冷却；模式四、P1/P2 不启用本扩展。

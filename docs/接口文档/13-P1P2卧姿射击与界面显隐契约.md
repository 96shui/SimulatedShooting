# 13 P1/P2 卧姿固定射击与界面显隐契约

## 目标

约束 P1 100m 射校与 P2 移动靶共同使用的卧姿固定射击体验，并把 UI、场景、玩法功能三方的责任拆开。三方只能依赖本契约、通用 DTO/事件和各自测试替身，不得直接引用彼此的具体实现。

## 产品不变量

- P1/P2 固定为卧姿射击，不提供姿态切换。
- 进入任一靶场时，玩家根节点已经位于并朝向该场景的固定射击点。
- 禁用连续移动、传送、攀爬和人工平移；靶场不需要玩家走到射击点。
- 真实 HMD 与双手房间尺度跟踪必须保留，禁止通过锁死 HMD Transform 实现“固定位置”。
- 无 VR 模式允许观察、瞄准和手部替身操作，但不允许 WASD/摇杆平移玩家根节点。
- 入场的大型交互 UI 与训练步枪均位于玩家正前方，二者使用独立场景锚点。
- 玩家确认开始后进入等待拾枪；有效拾取后手握把时，大型交互 UI 自动隐藏，P1 进入实射、P2 进入 3 秒倒计时。
- P1 每轮结束显示弹着分析，点击进入下一轮后隐藏；最终结束显示评级。
- P2 路线结束显示结算；重新训练返回速度设置，下一次确认并拾枪后再次隐藏。
- 实弹阶段可保留最小只读 HUD，但不得保留可交互大面板或遮挡觇孔/目标。

## 分层和独立开发边界

| 负责人 | 输入 | 输出 | 禁止事项 |
|---|---|---|---|
| UI | `TrainingPresentationDto`、HUD/结果 DTO、UI 命令结果 | 按钮命令、View 显隐和渲染 | 不查找场景锚点、不读取武器组件、不判断轮次结束 |
| 场景 | `TrainingRangeSceneBindings`、标准化视觉驱动输入 | 玩家/UI/武器/目标锚点和视觉表现 | 不创建 Session、不决定 UI 阶段、不计算评级/弹药/禁射 |
| 玩法功能 | 输入/武器事件、时间、命中快照 | Session、Presentation、HUD、结果 DTO/事件 | 不引用 Canvas、Transform、Scene、XR Interactor 具体类型 |
| 审核测试与优化 | 分阶段检查冻结契约、黑盒入口、测试证据 | 审核记录、回归、性能/体验报告；不占 task 编号 | 不另建第二套生产规则绕过三方实现 |

UI、场景、玩法功能在本契约冻结后并行开发。任何一方的任务规格不得把另一方具体任务写成开工前置；真实实现只在集成门禁阶段替换测试替身。

## 表现状态

```csharp
public enum TrainingPresentationPhase
{
    ModeEntry,
    AwaitingStartConfirmation,
    AwaitingWeaponPickup,
    LiveFire,
    RoundReview,
    SessionResults,
    Exiting
}

public enum TrainingPostureMode
{
    ProneFixed
}

public readonly struct TrainingPresentationDto
{
    public string SessionId { get; init; }
    public TrainingMode Mode { get; init; }
    public TrainingPresentationPhase Phase { get; init; }
    public TrainingPostureMode Posture { get; init; }
    public ScreenId ActiveScreen { get; init; }
    public bool LargePanelVisible { get; init; }
    public bool MinimalHudVisible { get; init; }
    public bool ShootingAllowed { get; init; }
    public bool ArtificialLocomotionAllowed { get; init; }
    public bool AwaitingWeaponPickup { get; init; }
    public string FiringStationId { get; init; }
    public string VisibilityReason { get; init; }
}
```

`LargePanelVisible` 是任务说明、速度设置、弹着分析和最终结算等大面板的唯一业务显隐来源。`ShootingAllowed`、`MinimalHudVisible` 与 `LargePanelVisible` 必须由展示阶段推导，UI 不得自行组合。CanvasGroup、GameObject Active 等具体表现由 UI 决定。

## 状态转换

| 当前状态 | 命令/事件 | 下一状态 | 大型 UI | 有效射击 |
|---|---|---|---:|---:|
| ModeEntry / AwaitingStartConfirmation | 页面加载 | AwaitingStartConfirmation | 显示 | 禁止 |
| AwaitingStartConfirmation | Start 成功 | AwaitingWeaponPickup | 显示 | 禁止 |
| AwaitingStartConfirmation | 提前拾枪 | 不变 | 显示并提示先确认 | 禁止 |
| AwaitingWeaponPickup | 后手有效拾枪 | LiveFire；P2 同时进入 Countdown | 隐藏 | 按模式状态决定 |
| LiveFire | P1 本轮第 3 发完成 | RoundReview | 显示分析 | 禁止 |
| RoundReview | NextRound 成功且武器仍可用 | LiveFire | 隐藏 | 允许 |
| RoundReview | NextRound 成功但武器已释放 | LiveFire（等待重新持枪） | 隐藏；最小 HUD 提示取枪 | 禁止，重新有效持枪后允许 |
| LiveFire | P1/P2 Session 完成 | SessionResults | 显示结算 | 禁止 |
| SessionResults | P1 Retry | AwaitingStartConfirmation | 显示任务说明 | 禁止 |
| SessionResults | P2 Retry | AwaitingStartConfirmation | 显示速度设置 | 禁止 |
| 任意非退出状态 | Back/Cancel | Exiting | 按路由处理 | 禁止 |

状态变化必须由玩法应用服务发布，UI 不得通过弹药文本、目标位置或武器 GameObject Active 自行推断。

## 服务和事件

```csharp
public interface ITrainingPresentationService
{
    ServiceResult<TrainingPresentationDto> Enter(TrainingMode mode);
    ServiceResult<TrainingPresentationDto> Get(string sessionId);
    ServiceResult<TrainingPresentationDto> ConfirmStart(string sessionId);
    ServiceResult<TrainingPresentationDto> HandleWeaponPickup(TrainingWeaponPickupEvent pickup);
    ServiceResult<TrainingPresentationDto> ContinueNextRound(string sessionId);
    ServiceResult<TrainingPresentationDto> NotifyMovingTargetCountdownElapsed(string sessionId);
    ServiceResult<TrainingPresentationDto> NotifyTrainingCompleted(string sessionId);
    ServiceResult<TrainingPresentationDto> Retry(string sessionId);
    ServiceResult<TrainingPresentationDto> Exit(string sessionId);
    ServiceResult<TrainingLocomotionPolicyDto> GetLocomotionPolicy(string sessionId);
    event Action<TrainingPresentationDto> PresentationChanged;
}

public readonly struct TrainingWeaponPickupEvent
{
    public string SessionId { get; init; }
    public string WeaponId { get; init; }
    public WeaponHoldState PreviousState { get; init; }
    public WeaponHoldState CurrentState { get; init; }
}
```

- `ITrainingPresentationService` 可以是现有应用服务的职责扩展，不要求新增全局单例。
- `Enter` 对应靶场页面加载，进入 `AwaitingStartConfirmation`；`ConfirmStart` 创建/更新 Session 后进入 `AwaitingWeaponPickup`。
- 只有有效的后手拾枪转换（`OnRack/Dropped → RearHandHeld` 或直接进入 `TwoHandHeld`）可以触发等待拾枪到 P1 实射 / P2 倒计时的转换。
- P2 有效拾枪后发布 `MovingTargetCountdownRequestedEvent`（3 秒）；倒计时结束调用 `NotifyMovingTargetCountdownElapsed` 才允许射击。P2 训练完成调用 `NotifyTrainingCompleted` 进入 `SessionResults`。
- 前手接入、持续 Grip、重复事件或视觉手切换不得重复隐藏 UI/启动轮次。
- `PresentationChanged` 必须在状态提交后发布；UI 收到事件时查询到的 DTO 必须与事件一致。
- `GetLocomotionPolicy` 对 P1/P2 固定返回禁用连续移动/传送/人工转向，并允许房间尺度头手追踪。

## 固定卧姿与输入策略

```csharp
public readonly struct TrainingLocomotionPolicyDto
{
    public TrainingMode Mode { get; init; }
    public TrainingPostureMode Posture { get; init; }
    public bool AllowContinuousMove { get; init; }
    public bool AllowTeleport { get; init; }
    public bool AllowArtificialTurn { get; init; }
    public bool AllowRoomScaleHeadAndHandTracking { get; init; }
}
```

P1/P2 固定值：前三项为 `false`，`AllowRoomScaleHeadAndHandTracking=true`。`IXRTrainingInput.MoveAxis/TurnAxis` 为 P3 保留，但 P1/P2 的应用协调器和 locomotion adapter 必须忽略这些输入。真实追踪造成的头手局部变化不能被回写或钳回。

## 场景绑定契约

每个 P1/P2 靶场必须提供一个 `TrainingRangeSceneBindings` 或等效组件，序列化引用：

- `PlayerRootAnchor`：玩家/XR Origin 固定根位置。
- `ProneHeadReference`：编辑态与无 VR 测试的卧姿视点参考，不驱动真实 HMD。
- `AimForwardAnchor`：主射界方向。
- `LargeUiAnchor`：大型交互 UI 正前方锚点。
- `MinimalHudAnchor`：最小只读 HUD 锚点。
- `WeaponRackAnchor`：训练步枪正前方放置点。
- `TargetRootAnchor`：固定靶或移动靶视觉根。

绑定组件只暴露引用和验证结果，不引用 Presenter、Session 服务或玩法状态机。UI 预制体由组合根绑定到 `LargeUiAnchor/MinimalHudAnchor`；玩法只使用 `FiringStationId` 和事件，不读取 Transform。

## 空间验收原则

- `LargeUiAnchor` 和 `WeaponRackAnchor` 均位于 `AimForwardAnchor` 正前方半空间，且互不遮挡。
- 大型 UI 位于卧姿自然视线范围，默认距离、角度和尺寸由场景配置，不散落在 UI 脚本中；最终以真实 VR 舒适度验收为准。
- 武器后握把处于卧姿自然伸手范围，玩家无需起身、走动或移动 XR Origin。
- UI/武器重定位只允许移动各自锚点或表现根，不允许写入 HMD Camera 跟踪姿态。

## 错误处理

| 条件 | 错误码/处理 |
|---|---|
| 未确认开始就拾枪 | `InvalidState`；UI 保持显示，射击禁止 |
| 重复拾枪事件 | 幂等返回当前状态，不重复启动轮次 |
| 非 RoundReview 请求下一轮 | `InvalidState` |
| 场景绑定缺失或重复 | 场景加载失败并输出可定位错误；不得使用名称猜测回退 |
| P1/P2 收到人工移动命令 | 安全忽略，不改变玩家根位置，不报持续错误 |
| UI 未收到显隐事件 | 重新启用时查询当前 DTO 自愈，不从场景状态反推 |

## 独立验收要求

- UI：使用假的 `TrainingPresentationDto` 逐状态验证显隐，不加载真实靶场或武器。
- 场景：使用场景绑定校验器和假的标准化目标进度验证锚点/视觉，不启动真实 Session 或 UI。
- 玩法：使用假的输入、武器事件、时钟和命中快照验证状态，不加载 Scene/Canvas。
- 集成：由审核测试与优化负责人加载真实实现，验证 P1/P2 完整顺序、事件只触发一次和场景卸载无残留。

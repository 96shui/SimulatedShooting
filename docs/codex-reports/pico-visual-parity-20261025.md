# PICO真机与Unity观感对齐：第一轮

## 目标与范围

用户反馈所有模式模糊、卡顿，墙面/地面重叠闪烁，希望尽量保留Unity当前场景效果。关联BDD01、接口11、P3场景task014及PICO构建部署说明。模型、贴图、布局、UI和训练规则不改；不将第一轮配置调整视为完整VR验收。

## 基线事实

- 已安装基线为main `27717ef`。读取头显现有应用日志存档到`Logs/PicoPerformance/before-app.log`（本地忽略）。原生OpenXR报告每眼1504×1504，双眼数组。
- PxrMetric包含多数90/90以及19/90、46/90等片段，GPU时间部分约8–11ms。日志没有逐条标记当前玩法/加载阶段，不能据此断言所有模式持续低帧率，也不能做相同机位的优化前后比较。
- 保存场景中的VR相机为0.01–1000m；桌面靶场相机为0.05–300m。过近的近裁剪面降低远处深度精度。
- 两个靶场各48个SandPatch薄片原高度0.006m；模式二起伏地面最高约0.037m，装饰片会与地面穿插。
- CombatSceneRenderProfile原来在所有平台强制桌面CombatQuality：HDR、90m、四级联阴影；不符合移动设备预算。

## 修改

1. Android专用Resources管线PicoStandalone：保留4xMSAA、URP比例1、完整纹理；使用35m、单级联2048硬阴影、关闭HDR及额外逐像素灯，保留方向光和环境光。桌面原配置保留。
2. Android自动策略设置XR渲染目标倍率1.25、viewport为1、禁止相机动态降分辨率，各向异性过滤4–8。相机近/远裁剪统一0.05–300m，只覆盖XR主视角、不覆盖无人机RenderTexture。新增一次启动日志报告实际尺寸。
3. PICO官方DisplayRefreshRateFeature开启，displayFrequency=72。这是预算目标，不能宣称实机稳定72Hz；注视点降画质保持关闭。
4. CombatSceneRenderProfile在Android保持移动管线，不切入桌面四级联配置。
5. 保留沙土片位置XZ、轮廓、材质和数量，仅将其Y提高到0.07m，避免与起伏地面交叉；模式二生成器同步。此为装饰几何约几厘米间距，不更改地面碰撞或射击规则。墙面残余闪烁仍需佩戴检查，未盲目删除墙面/模型。
6. APK改为BuildOptions.None正式构建，减少开发构建开销；ADB日志仍保留。

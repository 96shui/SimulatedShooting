## 遇到的问题与处理

### 上一轮失败原因是 Unity 许可失效

上一轮发生于 `2026-11-12 19:21:29` 至 `19:21:40`，当时基线为 `6642b40d3f13793bc4c52ba8fe44dc4fd9b654da`，另有工作区改动。Unity 在加载项目及进入构建入口前退出，退出码 `1`，没有生成该轮 APK。直接错误为：


该轮根因是本机 Editor entitlement 失效，与 IL2CPP、Gradle 或游戏实现无关。历史记录仍在 `Logs/pico-apk-20261112/`。用户现已恢复许可；本轮两次日志均出现 `Successfully resolved entitlement details` 并进入构建入口，最终退出码 `0`。启动阶段虽有许可客户端握手及 access token 提示，随后 entitlement 解析成功，未阻塞本轮出包。

### Gradle 直连 Google Maven 等待

首次恢复构建通过许可、资源与 IL2CPP 后，停在 `Building Gradle project`。线程栈显示 `Daemon worker` 位于 `PlainSocketImpl.waitForConnect` → Gradle HTTP 仓库元数据 HEAD 请求，网络连接处于直连 Google 地址的 `SynSent`。

为区分网络、仓库与缓存问题，使用 Unity 自带 OpenJDK 对实际仓库资源执行带 5 秒连接超时的最小 Java HEAD 探测：

```text
https://dl.google.com/dl/android/maven2/com/android/tools/build/gradle/7.4.2/gradle-7.4.2.pom
```

| 网络路径 | 第一次 | 第二次 |
|---|---|---|
| Java 默认直连 | `SocketTimeoutException: connect timed out`，`5.274s`，退出码 `1` | 同错误，`5.264s`，退出码 `1` |
| Java 显式使用现有代理 `127.0.0.1:7890` | `HTTP=200`，`1.174s`，退出码 `0` | `HTTP=200`，`0.398s`，退出码 `0` |

本机已有 `HTTPS_PROXY=http://127.0.0.1:7890`，Java/Gradle 没有自动将其用于此次连接。确认原因后，仅结束本轮 Java client `52192` 与 Gradle daemon `82504`，让 Unity 报告失败并正常释放项目锁。第一次尝试退出码 `1` 是主动中止后的结果，不将其描述为自然发生的编译失败。

还原自动改写的受跟踪配置，在重试构建进程中补充 Java HTTP/HTTPS 代理参数后，原入口成功。未修改 Gradle 模板、依赖版本、游戏逻辑、UI 文案、资源或签名代码。

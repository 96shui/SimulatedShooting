# 支撑手抓取与模式四清剿流程

## 支撑手响应

发现两处会漏掉抓取的单帧条件：保存的 XRI 交互器使用 StateChange，战斗输入服务也只在 FrontGripPressed 且范围事实同帧有效时接入支撑手。按键先于进入范围、或左右握把近乎同时按下时，需要重新松开再按。

- 支撑手半径从 0.12m 改为 0.22m，后握把保持 0.10m。
- 共享 XR Origin 及 MainScene、ZeroingRangeScene、MovingTargetRangeScene 的近远/直接交互器保存为 State。步枪 Awake 和 Hover 回调也处理运行时后生成的交互器。
- CombatInputController 使用支撑手 Held 与有效范围组合接入，不再依赖 Pressed 单帧。换弹禁握、追踪、先有后手以及切肩门禁继续有效。

## 模式四

- UrbanService 仅选择 Building 组 3–6 个敌人，街道敌人固定 0。CombatScene 删除两处街道敌人候选点和对应估计锚点，构建器也不再创建它们；配置校验不要求街道候选容量。
- 开局直接进入 UrbanBuildingHud；开门无需先进入建筑阶段。玩家在同楼层房门 3m 内看到开门提示，移除检查房间和返回街道按钮及搜索进度显示。
- RoomDto 增加可选 EntryWorldPosition，生产场景使用现有房间中心。开门先发布门视觉/清除导航阻挡，再请求队友到室内目标；通过原有导航回执更新位置，不瞬移。
- 入室期间导航失败最多等待 0.15s 重试，避免门的 NavMesh carving 更新延迟引入原来 1s 的等待。玩家到入口附近后恢复正常跟随；模式三跟随策略保持原路径。
- 原胜利判断保留：玩家死亡优先失败，玩家存活、任务活跃且全部登记敌人确认死亡时立即胜利。现在登记列表只有室内敌人，不需要街道清理或搜索。

## 完成的检查

- Unity 请求编译完成，无 error CS。
- 保存场景只读核对：P1/P2 步枪支撑手范围均为 0.22m；MainScene/P1/P2/CombatScene 的相关交互器均为 State；无未保存场景。
- CombatScene 定义校验通过：室内候选点 6，室外候选点 0，5 个房间均有室内入口世界坐标；ValidateBindings 返回空错误列表。
- 5 个入口均可在 0.6m 内找到 NavMesh 表面，楼层高度分别匹配 0m、3.6m、7.2m。该检查只确认入口数据，不等于验证动态开门后完整的队友路径。
- 未新增或运行自动化测试，未进行头显验收。旧 12cm/Pressed/街道敌人/阶段切换测试需要按最新 BDD 与接口修订更新后再运行。

## 实机待验

1. 先按住左握把再进入支撑点，以及左右握把几乎同时按下，均能及时形成双手持枪。
2. 松开、失去追踪、换弹禁握和切肩后支撑手不会错误残留或隔空抓取。
3. 模式四从建筑 HUD 开始，靠近各楼层门点击开门即可让队友跟进；门动画、玩家碰撞、队友导航需实机观察。
4. 仅存在室内敌人，最后一名确认击杀后显示胜利，玩家死亡仍失败。

本轮没有提交或推送，保留既有未提交射校和设置改动。

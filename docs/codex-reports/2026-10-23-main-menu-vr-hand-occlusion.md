# 2026-10-23 MainScene启动手臂遮挡修复

对应用户截图、BDD34、接口26、P1 UI task008及既有VR手部显示组件。

## 现场与原因

修复前直接读取了用户当前运行中的MainScene：HMD相机世界坐标为`(0,0.0768,-2.5893)`，左手显示根节点为`(0,0.0518,-2.5093)`，即仅差手模固定偏移，手柄与头显处于重合的默认跟踪位置。人物模型始终显示，没有未跟踪或近头遮挡保护。已用Unity MCP保存修复前原生相机截图和运行对象记录。

## 修改

`VRHandPresentation`仅在MainScene中增加人物网格显示保护：

- 手柄缺少有效位置跟踪时隐藏对应手臂；优先读取Input System XR设备，保留旧XR接口回退。
- 即使设备已跟踪，手柄距头显小于15cm，或手臂网格包围相机/距相机不足3cm，也暂时隐藏对应网格。
- 使用Renderer.forceRenderingOff，不关闭控制器、交互器、UI射线、输入动作，也不移动HMD或伪造手柄姿态。
- 跟踪和距离正常后自动恢复；定时模型扫描保留原渲染标志，禁用/退出时恢复初始状态。
- 渲染前检查排在手部姿态更新之后，避免最终渲染仍使用旧包围盒。训练场景不使用该主菜单保护，保留原握枪、镜像及换弹显示。

## 验证

新增真实MainScene PlayMode回归，通过XR设备状态替身与实际TrackedPoseDriver驱动：未跟踪→恢复位置→网格覆盖相机→手柄贴头→离开→定时扫描→再次失去跟踪→恢复。修复前在“未跟踪仍显示手臂”断言失败；修复后通过。另验证训练场景不继承菜单隐藏状态。

已查看原生相机截图：未跟踪时菜单无遮挡，跟踪正常后双手和菜单射线正常出现。证据见[evidence/main-menu-hand-occlusion-20261023](evidence/main-menu-hand-occlusion-20261023)。其中设备状态替身截图不冒充头显实机截图；用户现场修复前截图来自实际运行中的MainScene。

最终相关PlayMode **12/12通过**，还覆盖真实扳机点击菜单按钮、场景切换和VR双手射校。先前两条新增保护测试也已通过；不重复计算为14项。

已恢复测试前OpenXR设置，并通过正常启动入口再次运行MainScene，未注入测试设备或强制VR模式。已人工查看`main-menu-native-restart.png`，确认用户现场启动路径不再出现手臂遮挡；Editor停留在MainScene Play Mode，便于直接复测。MainScene保存资产未改，`git diff --check`通过；未提交或推送。

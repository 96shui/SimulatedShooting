# VR射击训练游戏阶段化整体需求说明书

## 总体定位

本项目是一款 Unity VR 射击训练游戏原型，面向现代军事训练模拟器方向。第一目标是在 Unity Editor 中完成可演示、可测试的训练闭环；VR 设备到位后，同一套功能需要支持真实头显和手柄验证。

画风尽量写实，优先保证场景比例、武器观感、射击弹道和后坐力可信。模型和贴图精度需要控制，避免影响 VR 帧率和迭代速度。

## 测试与输入要求

- 无 VR 设备时，必须能通过 Unity Editor、XR Device Simulator 或输入测试替身完成核心流程测试。
- 有 VR 设备时，必须能通过真实头显和手柄测试双手持枪、扳机开火、按钮换弹、左右肩切换和 HUD 可读性。
- 所有输入应通过可替换的输入适配层进入业务服务，业务服务不直接读取硬件输入。

## BDD 协作要求

项目高度使用 AI 协作，所有任务必须遵循当前 BDD 工作流：

1. 先明确需求范围。
2. 更新或确认 `docs/BDD/screens/*.feature.md`。
3. 更新或确认 `docs/接口文档/*.md`。
4. 再实现代码、场景、UI 和测试。
5. 行为或接口变化时，同步更新 BDD 和接口文档。

## 第一阶段：100m 射校原型闭环

目标：完成一个可演示、可测试、可扩展的 100m 精度射校训练闭环。

### 必须实现

- 主菜单进入 100m 精度射校靶。
- 100m 任务说明页面。
- 第一人称射击 HUD。
- 100m 射校固定为卧姿打靶；玩家进入场景时已经位于并朝向射击点，不提供连续移动、传送或通过摇杆改变射击位置的功能，真实头部和双手跟踪仍正常工作。
- 任务说明 UI 与训练步枪初始放置在卧姿玩家正前方的独立锚点上，不得默认绑定在相机或玩家身上。
- 玩家确认开始并拿起训练步枪后，大型交互 UI 自动隐藏；每轮 3 发结束后弹着分析 UI 自动出现在玩家正前方；点击进入下一轮后分析 UI 再次隐藏，最终评级 UI 在训练结束后出现。
- 右手控制器靠近后手握把后，通过 Grip/握把键拾取步枪；左手控制器靠近前握把或护木后，通过 Grip/握把键形成左前右后的双手持枪。
- 双手持枪完成后，右手控制器扳机开火；未拾枪、仅左手接触或未形成有效双手持枪时不得产生有效射击。
- 真实 VR 视角完全由 HMD 跟踪姿态驱动，不因拾枪、瞄准或后坐力强制移动、旋转、缩放视野或切换到代理相机；玩家通过移动头部和枪体自然对齐机械瞄具。
- 按按钮换弹。
- 左右肩切换。
- 简单但可感知的后坐力和枪口抖动。
- 弹着点由玩家瞄准稳定性决定，不做纯随机散布。
- 开局生成一次固定弹着偏移，三轮共用。
- 每轮 3 发，共最多 3 轮。
- 每轮结束显示弹着分析：上下/左右偏差、准星柱调整方向和角度、觇孔调整方向和格数。
- 玩家应用调整后进入下一轮。
- 调整后 3 发全部进入 10 环则通过。
- 评级规则：第 1 轮通过为优秀，第 2 轮为良好，第 3 轮为及格，3 轮未通过为不及格。

### 基础服务

- `ServiceResult<T>`
- `ErrorCode`
- `IGameEventBus`
- `IUIRouter`
- `ITrainingSessionService`
- `IHUDService`
- `IZeroingService`
- 输入适配接口
- 基础武器控制和弹药消耗

### 场景范围

- 小型 100m 靶场。
- 写实风格原型资产。
- 包含卧姿固定射击位、正前方 UI/武器锚点、靶标、基础环境、光照和测试出生点。

### 暂不实现

- 移动靶。
- 敌人 AI。
- 队友 AI。
- 堑壕和城镇战斗。
- 历史训练记录。
- 真实弹匣插拔、拉机柄、保险、卡弹等高拟真枪械操作。

### 验收标准

- 无 VR 设备时可在 Unity Editor 完成完整 100m 射校流程。
- 有 VR 设备时可完成同样流程。
- HUD 数据来自服务层，不写死示例值。
- 评级和调整计算由服务层完成。
- EditMode 测试覆盖偏差计算、调整计算、评级规则。
- PlayMode 测试覆盖进入训练、完成一轮、进入分析页、进入结算页。
- PlayMode 测试覆盖无移动、卧姿锚点、拾枪隐藏 UI、轮次结束显示 UI、下一轮隐藏 UI。

## 第二阶段：移动靶闭环

目标：在 100m 射校（P1）稳定基础上，新增第二个训练模式——移动目标射击闭环。沿用 P1 的武器、输入、HUD、弹药与 Session 能力。

### 必须实现

- 主菜单进入移动目标射击。
- 移动靶设置页：速度选择 3m/s、4m/s、5m/s（默认 4m/s 或项目配置默认值）。
- 移动靶训练同样固定为卧姿；玩家进入场景时已位于射击点，不提供连续移动、传送或人工改变射击位置。
- 速度设置 UI 与训练步枪位于玩家正前方；确认开始后拿起步枪，设置 UI 自动隐藏并进入 3 秒等待；训练结束后结算 UI 自动在正前方出现。
- 进入射击视角后等待 3 秒，靶子开始运动。
- 靶子从右向左运动，到左端停留 2 秒，停留期间禁止射击，再返回右端结束。
- 两发起射连射模式：快速扣动一次固定射出两发；第二发后仍持续按住扳机则按配置射速继续逐发连射，松开、弹药耗尽、进入禁射阶段或训练结束时立即停止；本局总弹药 10 发。
- 沿用 P1 训练主武器与觇孔瞄准。
- 按命中数评级：3 发及格，4 发良好，5 发及以上优秀。
- HUD 与弹药服务在 P1 能力上扩展到移动靶模式（禁射不消耗弹药）。

### 场景范围

- 小型移动靶靶场。
- 卧姿固定射击位和独立的 UI/武器/玩家锚点。
- 左右端点标识。
- 单一日间环境即可。

### 验收标准

- 100m 射校仍可稳定运行。
- 移动靶可在无 VR 和有 VR 两种方式下测试。
- 靶子运动、端点禁射、两发起射/持续连射、逐发弹药消耗和命中评级由服务控制。
- EditMode 测试覆盖移动靶状态机、命中评级、端点禁射。
- PlayMode 测试覆盖速度选择、开始训练、HUD 刷新、结算跳转。
- PlayMode 测试覆盖卧姿入场、无人工移动、拾枪隐藏设置 UI、训练结束显示结算 UI。

## 第三阶段：小型堑壕与城镇战斗原型

目标：完成小规模战术训练玩法，先验证敌人、队友、搜索、胜负闭环。

### 堑壕射击

- 先做 1 张小型堑壕地图，后续扩展到 2 张。
- 玩家和两名队友组成 3 人纵队。
- 玩家在最前，第二名队友在玩家后方朝前，第三名队友在最后朝后警戒。
- 敌人简单 AI：开局生成 3-5 个，出现在预设点附近，发现玩家后射击，被命中后死亡，尸体不消失。
- 小地图显示玩家、队友和敌人标红位置。
- 搜索完堑壕并消灭所有敌人则胜利。
- 玩家血量归零则失败。

### 城镇攻防

- 先做小型城镇场景：一条街、一栋 3 层楼、3-5 个可搜索房间。
- 街道敌人 1-2 名。
- 建筑敌人 3-6 名。
- 敌人分布在楼道拐角和房间内。
- 搜索完楼房并消灭所有敌人则胜利。
- 玩家血量归零则失败。

### 战术动作

- 姿态先做站立、蹲下、卧倒状态切换和视角高度变化。
- 换肩射击沿用前两阶段武器系统。
- 拐角射击先做简化版，允许玩家在特定拐角位置伸枪射击。
- 队友指令延后，后续再加手榴弹、火力支援、掩护换弹。

### 暂不实现

- 高级敌人 AI：巡逻、找掩体、包抄、复杂投掷逻辑。
- 高级队友 AI：自动掩护、拉回玩家、火力压制、投掷手榴弹。
- 大型开放地图。
- 复杂伤害部位系统。
- 医疗救援系统。

### 验收标准

- 堑壕小地图、搜索进度、敌人清除、胜负结算可跑通。
- 城镇街道、进入建筑、房间搜索、敌人清除、胜负结算可跑通。
- 简单血量机制有效。
- 敌人和队友逻辑由服务或 AI 层控制，不由 UI 按钮直接创建或修改。
- 无 VR 设备时仍可通过模拟输入完成测试。
- 有 VR 设备时验证移动、瞄准、HUD 可读性和基本射击手感。

## 四人分工

### 场景负责人

- 100m 靶场、移动靶靶场、小型堑壕、小型城镇。
- 灯光、材质、NavMesh、出生点、掩体、性能优化。
- 控制模型和贴图精度，保证 VR 原型流畅。

### UI 负责人

- 主菜单、模式选择、100m 任务说明、HUD、弹着分析、评级。
- 移动靶设置（速度）、HUD、结算。
- 堑壕/城镇 HUD、小地图、结算。
- 所有 UI 按 BDD 命名和测试 ID 规范实现。

### 玩法功能负责人

- 统一负责通用 DTO、错误码、事件总线、页面路由、Session、HUD 聚合和训练状态机。
- 统一负责输入适配、武器控制、双手持枪、扳机、换弹、后坐力、弹道和命中反馈。
- 负责 100m 射校与移动靶服务，以及后续敌人、队友、血量和伤害玩法。
- 只依赖冻结接口，不直接引用 UI 控件或具体场景对象。

### 审核、测试与优化负责人

- 冻结和审查跨 UI、场景、玩法的契约、测试 ID、Prefab 绑定与任务边界。
- 独立建立 EditMode/PlayMode/无 VR 端到端测试和 P1/P2 回归门禁。
- 审查代码分层、场景引用、事件生命周期、错误/警告与测试可追溯性。
- 负责 VR 性能、加载卸载、资源预算、交互舒适度和最终优化，不代替三位实现负责人完成其主体功能。
- 不领取生产 task 编号；按各阶段审核清单在开发前、分线完成、候选集成和阶段收口时给出审核结论。

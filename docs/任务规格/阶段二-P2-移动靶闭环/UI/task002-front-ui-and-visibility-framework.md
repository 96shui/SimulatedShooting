# task002：P1/P2 正前方 UI、最小 HUD 与显隐框架

## 负责人

UI。

## 目标

建立 P1/P2 共用、可脱离真实场景运行的 World Space UI 框架：大型交互 UI 与只读最小 HUD 分根节点，支持模式进入、等待取枪、实射隐藏、轮次复盘和最终结算显隐；同步把 P1 页面改造成卧姿视角可用。

## 前置条件

已冻结的 DTO、事件、稳定 ID 和 UI 测试数据序列可用。不得依赖 task001、task003 或真实 P1/P2 场景实现。

## 实现内容

### 1. 共用根节点与锚点适配

- 建立 `LargePanelRoot`：任务说明、速度设置、弹着分析、评级、移动靶结算等可交互大型面板都置于该根节点。
- 建立 `MinimalHudRoot`：只放实射所需的只读、低遮挡信息；不得包含下一轮、重试等交互按钮。
- 提供只依赖通用 Anchor 接口的空间挂接组件；缺少 Anchor 时给出明确错误并可在测试场景使用默认 Fake Anchor。
- UI 自身不决定具体世界坐标、卧姿相机高度或武器架距离。

### 2. 显隐 Presenter

- Presenter 订阅完整 `TrainingPresentationDto`，原子应用大型 UI、最小 HUD、当前面板、交互可用和输入焦点。
- `AwaitingWeaponPickup` 仍显示大型 UI/取枪提示；有效取枪后的倒计时/实射隐藏大型 UI。
- `RoundReview`、`Results` 自动显示对应大型面板并禁用无关按钮。
- 乱序或重复事件不得造成闪烁；场景退出时必须退订。

### 3. P1 页面卧姿改造

- 100m 任务说明在卧姿正前方可读且可由射线点击。
- 三发结束后弹着分析自动出现；下一轮按钮只发送命令，收到新状态后才隐藏。
- 最终评级自动出现；评级、散布、射弹数据均来自 DTO。
- 删除/停用脚步提示、站立高度假设和任何行走引导文案。

### 4. 测试 ID 与可访问性

- 遵守 `Screen_`、`Button_`、`Text_`、`Hud_` 命名，所有关键控件提供稳定测试 ID。
- 文本不使用写死示例数字；空值、加载中、服务拒绝和重复点击都有确定表现。
- 确保卧姿常见视距下字号、对比度、点击热区和焦点状态可用；实机数值在阶段审核节点 D 复验。

## 交付物

- 共用 World Space UI Prefab/组件、`LargePanelRoot`、`MinimalHudRoot`。
- 展示状态 Presenter 和 Anchor 适配接口。
- P1 任务说明、分析、评级与显隐流程改造。
- 稳定测试 ID 清单和 DTO 字段到控件的映射表。
- 使用 Fake DTO/命令 Spy 的无场景 PlayMode 测试。

## 测试要求

- 在空白 PlayMode 测试场景依次注入模式入口、等待取枪、实射、轮次复盘、下一轮、最终结果状态。
- 验证开始后未取枪时大型 UI 不隐藏；有效取枪状态到达后才隐藏。
- 验证实射中大型 UI 不可点击且最小 HUD不遮挡中心瞄准保留区。
- 验证 P1 三发后分析出现、点击下一轮仅发送一次命令、收到状态后隐藏、最终评级出现。
- 验证重复/乱序快照、对象禁用/启用和场景卸载后无重复订阅。
- 验证所有关键节点可通过稳定测试 ID 定位。

## 验收标准

- 不加载真实 P1/P2 场景和玩法服务即可完成 UI 全状态演示与测试。
- Prefab 没有指向场景对象、武器或玩法具体类的序列化引用。
- UI 不含移动靶、评级、弹药或完成规则。
- P1 卧姿视角和新显隐时序与 BDD 一致。

## 联调契约（非实现依赖）

- 场景只提供两个独立 Anchor；UI 通过适配器挂接，不关心场景层级。
- 玩法只提供 DTO/事件/命令接口；UI 可以持续使用冻结的 Fake 数据开发。
- 真正绑定在阶段审核节点 D 的组合根集成中完成。

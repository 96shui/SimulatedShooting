# 阶段二 P2：卧姿固定射击与移动靶闭环

## 阶段目标

P2 同时统一 P1/P2 的固定卧姿射击体验，并完成移动靶训练闭环：玩家入场即在射击点，不提供走路或传送；准备 UI 与训练步枪位于正前方；确认开始并有效拾枪后大型 UI 隐藏；轮次或训练结束后分析/结算 UI 自动出现。

移动靶规则为 3/4/5 m/s、3 秒倒计时、40m 右→左→右、左端停留 2 秒禁射、两发起射/长按连射、10 发弹药和命中评级。

## 产品范围

必须实现：

1. P1/P2 入场均固定到卧姿射击点和主射界朝向。
2. 禁用连续移动、传送、攀爬和无 VR 平移；保留真实 HMD/双手跟踪。
3. 大型准备 UI、最小 HUD 和训练步枪使用正前方独立锚点。
4. Start 后等待拾枪；有效拾枪隐藏大型 UI，P1 进入实射、P2 进入 3 秒倒计时。
5. P1 每轮结束显示分析，NextRound 后隐藏；最终显示评级。
6. P2 目标按 40m 右→左→右运动，左端停留 2 秒禁射，右端结算。
7. P2 快速扣动一次固定射出两发；第二发后仍保持 Trigger 则继续逐发连射。
8. P2 连射在释放、无弹、禁射、训练完成或武器/跟踪失效时停止；禁射恢复后必须释放并重新扣动才能再射。
9. 实弹阶段只允许保留不遮挡瞄准线的最小只读 HUD。
10. P1/P2 均提供无 VR 自动化路径和真实 VR 验收项。

明确不做：动态昼夜、夜间 HUD、夜视、武器库/武器墙、选枪、全局设置、人工行走、敌人/队友 AI、堑壕/城镇和高拟真弹匣操作。

## 独立轨道规则

- UI、场景、玩法功能只依赖冻结文档和各自测试替身；不能把另一条真实实现列为开工前置。
- UI 不引用具体 Scene、Transform、XR Interactor 或武器 MonoBehaviour。
- 场景不引用 Presenter、Session 或玩法具体实现，不计算连射、弹药、禁射和结算。
- 玩法不引用 Canvas、GameObject、Scene、Transform、Animator 或 XR 具体类型。
- 连射计时属于玩法功能，使用可注入时钟；场景只消费逐发 ShotId 视觉事件，UI 只渲染连射状态 DTO。
- 真实集成只通过 Composition Root 和适配器完成。

## 执行顺序

1. 审核节点 A：审核冻结文档，但不建立审核 task。
2. 第一并行批：task001、task002、task003，各自使用 Fake 独立开发。
3. 审核节点 B：分别审核共用玩法、UI、场景框架。
4. 第二并行批：玩法 task004→task007；UI task005；场景 task006，三条轨道互不等待真实实现。
5. 审核节点 C：分别审核移动靶玩法、UI、场景候选版本。
6. 审核节点 D：通过组合根集成并执行 P1/P2 全回归、VR 和性能验收。

## 完成口径

- 7 个生产任务都必须完成自身 EditMode/PlayMode 测试和 BDD 追溯。
- 四个审核节点均通过后才能宣称 P2 完成；审核本身不占 task 编号。
- 快速扣动和长按连射必须分别有自动化测试，不能只测一次 Fire 方法调用。
- P1 长按不得连射，必须保留单发回归证据。
- 自动化不得冒充真实 VR 舒适度；无设备时明确列出待补验项。

## BDD 场景追溯

本任务不实现下列场景的最终表现，但必须保证每个场景都有明确的服务命令、查询 DTO、事件、错误分支和稳定测试 ID：

- `02-游戏主界面`：进入移动目标射击设置。
- `03-训练模式选择`：选择移动靶卡片、确认进入、返回主界面。
- `08-移动靶设置`：速度选择、开始训练、返回。
- `09-移动靶HUD`：3 秒等待、点射耗弹、命中更新、端点禁射、抵达终点结算。
- `11-移动靶结算`：命中评级、训练摘要、点射记录、重新训练、返回。


## P1 回归准入硬门禁

- P1 task014 已提供由无 VR 输入替身贯穿主菜单、场景、武器、3 发射击、弹着分析、应用调整和结算的 PlayMode 夹具。
- P1 task014 至少覆盖第 1 轮优秀和 3 轮不及格两个可控结果。
- P1 task015 / task016 完成 UI 测试 ID、场景与性能收口。
- P2 契约和实现不得改变 P1 的 3 发一轮、HUD Key、训练武器或射校评级来换取 P2 测试通过。

## 必须先解决的接口缺口

1. **两发点射原子命令**：一次点射包含两发射击输入、两个射击序号、逐发命中快照、一次点射记录和最终弹药快照；禁止先扣弹后回滚。
2. **弹药唯一权威与部分点射结算**：`IAmmoService/AmmoDto` 是唯一数据源；`MovingTargetSessionDto` 不得维护可独立修改的第二套弹药字段。路线结束时实际消耗可为 0-10 发，记录为 0-5 条。
3. **禁射前置门禁**：等待/端点禁射状态下不得产生弹药消耗、后坐力、命中反馈。
4. **路线配置与进度**：可注入路线长度、倒计时和端点停留配置；DTO 提供可驱动场景的规范化进度。
5. **Session 生命周期**：明确创建/开始/完成/取消顺序与唯一 SessionId 来源。
6. **P2 UIEvent 与返回路由**：补齐移动靶开始/重训/返回事件；“重新训练”冻结为返回移动靶设置页并保留上次速度选择。
7. **HUD/结算稳定字段**：冻结 countdown、ammo、fireMode、hits、speed、direction、shootState、burstRhythm、endpointHold 等 Key；不允许 UI 从自由文本反推评级。
8. **P2 Unity 稳定 ID 与绑定**：补移动路线、端点、目标、HUD 字段的命名与测试 ID。
9. **速度档位**：仅支持 3/4/5 m/s。

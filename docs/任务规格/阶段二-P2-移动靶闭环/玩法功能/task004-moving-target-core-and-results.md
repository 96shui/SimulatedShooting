# task004：移动靶核心、路线、计分与结算

## 负责人

玩法功能。

## 目标

实现可确定性测试的移动靶训练核心：速度配置、3 秒倒计时、40m 右→左→右、左端停留禁射、训练完成、HUD 聚合、评级和结算。实现不依赖 Unity 场景 Transform，场景只负责表现。

## 前置条件

玩法同线 task001 完成。不得依赖 task002、task003、task005 或 task006 的真实实现。

## 冻结规则

- 用户选择 3 / 4 / 5 m/s 之一，配置在训练开始时写入 Session，实射中不可修改。
- 有效取枪后先倒计时 3 秒，之后目标从约定端点开始运动。
- 横向路线长 40m：从右端出发，到左端停留 2 秒并禁射，再返回右端直接结束训练。
- 运动进度、所在段、方向、剩余停留时间都来自玩法状态，不从场景 Transform 反推。
- 命中数、射击数、命中率、评级和结算基于服务层原始记录，不读取 UI 文本。

## 实现内容

### 1. 配置与 Session

- 校验速度枚举/数值，仅接受 3、4、5 m/s。
- 创建带固定种子、模式、速度、卧姿射击点和弹药初值的 Session。
- 对非法速度、重复开始、实射中改速返回稳定错误码。

### 2. 确定性状态机

- 以注入时钟或显式 `Tick(deltaTime)` 驱动倒计时、运动和端点停留。
- 输出状态至少包含：阶段、方向、`RouteProgress01`、`LegProgress01`、当前速度、倒计时、`EndpointHoldSecondsRemaining`、开火许可。
- 大步长 Tick 必须能跨越端点并正确消耗剩余时间，不丢失状态转换。
- 暂停、退出、重试必须有确定行为，不依赖 `Time.time` 静态读取。

### 3. 命中与训练完成

- 接收标准化射击/命中记录，校验 Session、shot ID 和发生阶段。
- 倒计时、端点停留、结算阶段的射击不得计入有效成绩。
- 对重复 shot ID 幂等，防止同一弹丸重复计分。
- 接收 task007 的逐发射击结果和序列结束记录；按路线完成条件结束训练并发布完成事件。

### 4. HUD 与结算

- 聚合 `HudDto`：倒计时、剩余弹药、两发起射/长按连射模式、当前连射状态、命中、速度、运动方向和必要状态提示。
- 生成 `MovingTargetResultDto`：总射击、命中、命中率、速度、用时、评级、射击序列和可追溯逐发记录。
- 评级算法使用独立纯函数和边界测试；显示文本映射留给 UI。
- 完成后通知 task001 的展示服务进入 `Results`，但不实例化 UI。

## 交付物

- 移动靶配置、状态机、路线推进、开火许可和完成判定服务。
- HUD/结果 DTO 聚合器、评级纯函数和事件定义。
- 固定时钟/显式 Tick 驱动的 EditMode 测试。
- 给场景视觉驱动和 UI Presenter 的示例 Fake 数据序列。

## 测试要求

- 3/4/5 m/s 的配置成功和非法值失败。
- 3 秒倒计时边界、0 秒转换和大步长 Tick。
- 40m 右→左与左→右两段的进度、左端方向翻转和右端完成。
- 左端停留 2 秒期间禁射，离开左端后恢复许可，抵达右端后进入结算。
- 倒计时/禁射期命中不计分，运动期合法命中计分，重复 shot ID 不重复。
- 0 命中、全命中和评级阈值上下边界。
- 重试后旧状态清空且固定种子重放结果一致。

## 验收标准

- 全部规则能在无场景、无 UI、无 VR 的 EditMode 测试中通过。
- 场景只需按归一化进度设置目标位置，不能成为状态真相源。
- UI 能完全通过 DTO 显示 HUD/结算，不需要知道路线 Transform 或评级算法。
- 不含昼夜、夜视、敌人 AI、动态路线生成或玩家移动。

# P2 分阶段审核清单

## 使用方式

审核、测试与优化负责人不领取 P2 task 编号，也不实现第二套 UI、场景或玩法。每个审核节点只检查当前阶段应交付的证据、记录问题和给出“通过 / 退回对应负责人”结论。

审核不改变任务依赖：UI、场景、玩法功能仍使用冻结契约和测试替身独立开发。跨层问题必须回到接口、适配器或对应负责人处理，不能由审核人临时增加硬引用。

## 审核节点 A：开发开始前

审核时机：task001、task002、task003 开始前。

需要审核：

- 需求、BDD、接口是否统一为固定卧姿、无人工移动、UI/枪正前方独立锚点、拾枪后隐藏大型 UI。
- P2 是否明确为“两发起射 + 长按连射”：快速扣动两发，第二发后保持则继续连射。
- 连射停止条件是否完整：释放、无弹、左端禁射、训练完成、武器/跟踪失效。
- P1 是否明确保持单发，不能被 P2 输入改造影响。
- DTO、事件、错误码、SceneId、测试 ID 和七个场景 Anchor 是否一致。
- UI、场景、玩法是否都能使用 Fake 数据独立开工，没有互相等待真实实现。
- 是否混入昼夜、夜视、武器库、设置、敌人 AI 或玩家行走等范围外内容。

输出：规格问题清单、冻结结论和证据路径。该审核不是 task，不计入功能完成率。

## 审核节点 B：共用卧姿框架完成后

审核时机：task001、task002、task003 分别提交候选版本后，可逐条独立审核。

玩法功能审核：

- P1/P2 展示状态机是否合法、幂等，开始前取枪是否无效。
- 有效取枪后 P1 进入实射、P2 进入倒计时，大型 UI 是否由 DTO 控制隐藏。
- P1 分析、下一轮和最终评级显隐是否回归通过。
- 连续移动、传送和人工转向策略是否关闭，同时保留真实头手追踪。
- 玩法核心是否没有 Scene、Canvas、XR、Transform 依赖。

UI 审核：

- 大型交互 UI 与最小只读 HUD 是否分根节点。
- UI 是否只消费 DTO/事件和发送命令，没有评级、弹药或完成条件计算。
- 空白测试场景能否用 Fake 状态完整演示入场、等待取枪、隐藏、复盘和结算。
- Prefab 是否没有真实场景、武器和玩法具体实现引用，测试 ID 是否稳定。

场景审核：

- P1/P2 是否从固定卧姿射击点开始，人工 Locomotion 是否确实不可用。
- HMD/双手追踪是否保留，没有锁死相机或每帧钳制头手 Transform。
- Player、Aim、Large UI、Minimal HUD、Weapon、Target 等 Anchor 是否完整且相互独立。
- 场景是否没有倒计时、显隐、弹药、评级或结算业务逻辑。

输出：三条独立审核记录。某一条不通过只退回该负责人，不阻塞另外两条继续工作。

## 审核节点 C：P2 玩法、UI、场景完成后

审核时机：task004、task005、task006、task007 分别完成自测后，真实集成前。

玩法功能重点审核：

- 3/4/5 m/s、3 秒倒计时、40m 右→左→右、左端 2 秒禁射和右端结算是否由确定性状态机控制。
- 快速 Trigger `Pressed→Released` 是否恰好两发，弹药不足 2 发是否整次拒绝。
- Trigger 保持到第二发之后是否继续逐发连射，释放后是否立即停止后续射击。
- 长按连射遇到左端禁射、无弹、训练结束、武器/跟踪失效是否立即终止。
- 禁射结束但 Trigger 未释放时是否不会自动恢复，必须释放后重新扣动。
- 连射是否由可注入时钟驱动；大步长 Tick、重复事件和延迟回调是否幂等。
- 10 发长按是否只产生 10 发；每发弹药、后坐力、弹道、命中、HUD 是否使用同一个 ShotId。
- P1 一次 Trigger 仍只射 1 发，三发一轮和评级是否回归通过。
- 结果是否保存实际扣动序列和序列内逐发记录，而不是按固定次数生成汇总记录。

UI 重点审核：

- HUD 是否明确显示“两发起射 / 长按连射”和当前 Idle/InitialTwoShots/ContinuousFire/Stopped 状态。
- 弹药、命中、禁射和连射状态是否逐发读取 DTO，不读武器组件或枪口焰数量。
- 快速两发、长按耗尽、释放停止、禁射停止的 Fake DTO 序列是否都有 PlayMode 测试。
- 结算是否按扣动序列展示实际发数、命中发数和逐发记录。
- 设置、实射最小 HUD、结算的大型 UI 显隐是否与共同契约一致。

场景重点审核：

- 场景改名、GUID、Build Settings、40m 路线、端点、Collider 和 LayerMask 是否正确。
- Fake 进度和逐发 ShotId 是否能独立驱动目标、枪口焰、弹道和命中表现。
- 场景是否没有 Trigger 连射计时、弹药扣减、禁射判定和命中评级。
- 白天固定视觉是否满足要求，且没有新增昼夜切换系统。

输出：三条准入结论、问题严重级别、责任人和复验结果。

## 审核节点 D：真实集成与阶段结束

审核时机：7 个生产任务都通过独立审核后。

需要审核：

- 真实实现是否只在 Composition Root/适配器组合，没有给 UI、场景、玩法增加反向引用。
- P1 无 VR 闭环：卧姿入场、取枪隐藏、单发、轮次分析、下一轮隐藏、最终评级。
- P2 无 VR 闭环：速度设置、取枪隐藏、倒计时、目标路线、快速两发、长按连射、禁射停火、右端结算、重试。
- 场景切换、重复训练、退出时 Session、事件、输入、连射调度和弹药预留是否清理干净。
- Unity Console 是否 0 error；warning 是否清零或逐项说明。
- EditMode、PlayMode 是否全量通过，并能追溯到 BDD 场景。
- VR 实机是否验证卧姿舒适度、UI/枪距离、Trigger 快速两发与长按连射、禁射停火、头手追踪和无误触移动。
- Profiler 是否记录 CPU、GPU、GC、Canvas 重建、连射调度和场景加载；优化是否未改变规则结果。

输出：阶段二验收报告、自动测试结果、VR 验收记录、性能对比和剩余风险。没有 VR 设备时必须明确列为待验，不能写成已完成。

## 审核人不做的事情

- 不领取 task 编号，不计入 P2 的 7 个生产任务。
- 不替玩法负责人实现状态机/连射，不替 UI 负责人制作页面，不替场景负责人搭建靶场。
- 不在审核现场改变产品范围或用跨层硬引用绕过契约。
- 不把“已有代码”“能进场景”或“后续联调”当作完成证据。

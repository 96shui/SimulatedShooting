# task006：移动靶场、40m 路线与白天视觉

## 负责人

场景。

## 目标

在 task003 固定卧姿场景壳上完成正式移动靶靶场：迁移误拼写场景名、建立 40m 左右路线和端点、配置目标与命中表面、完成白天训练环境及性能基线。所有运动和阶段表现由 Fake/真实视觉状态驱动，场景不计算玩法规则。

## 实现内容

### 1. 场景迁移与稳定标识

- 将现有 `Assets/Scenes/MovingargetScene.unity` 迁移为语义正确的 `MovingTargetRangeScene.unity`。
- 移动原 `.meta` 一并保留 GUID；同步更新 Build Settings、SceneId 映射、场景测试和文档引用。
- 移除从 P1 复制而来的错误页面 ID、测试 ID 和对象命名；稳定标识按接口文档统一。
- 迁移前后分别做场景序列化引用和缺失脚本检查。

### 2. 移动靶场 Blockout

- 使用 task003 的唯一卧姿射击点、Aim、UI、HUD、Weapon、Target Anchor，不新增玩家行走路线。
- 构建清晰的射界、掩体/安全边界、目标背景和 40m 横向运动区域。
- 左右端点与路线在编辑器可视化且有明确单位/方向，路线实际长度误差在约定容差内。
- 白天固定光照保证目标、准星背景和 UI 对比度；不添加太阳运动、时钟或昼夜切换脚本。

### 3. 路线与视觉驱动

- 建立 `MovingTargetRouteBinding`，只暴露左端点、右端点、目标根和必要视觉组件。
- 视觉驱动接收 `RouteProgress01`、方向、端点停留和开火许可，将归一化状态映射到 Transform/Animator/材质。
- 禁止从 Transform 位置反写运动进度、命中率或训练阶段。
- 用冻结的 Fake 时间轴覆盖 3/4/5 m/s 观感、左端停留、方向翻转、右端结束和重试复位。

### 4. 目标与命中表面

- 目标 Collider、可命中区域、非目标环境层和射线/弹丸 LayerMask 明确分离。
- 命中适配器只生成标准化命中输入，不计算是否计分、评级或训练完成。
- 目标视觉反馈由已确认事件驱动；预测命中或重复命中不得直接改玩法数据。
- 枪口焰、击发声、后坐力、曳光和命中表现逐发消费唯一 ShotId；场景不得自行根据 Trigger Held 生成额外子弹。

### 5. 视觉与性能

- 完成白天环境的基础材质、光照、阴影、距离雾和可读性收口，风格与 P1 一致。
- 建立移动目标、实射和结算空壳三种状态的 Profiler 基线。
- 避免每帧查找、材质实例泄漏、无界粒子和不必要实时灯光；场景优化不改变 40m 路线和命中表面。

## 交付物

- `MovingTargetRangeScene.unity` 及保留 GUID 的 `.meta` 迁移。
- 40m 路线、左右端点、移动目标 Prefab/绑定、命中表面和白天环境。
- `MovingTargetRouteBinding`、视觉驱动、Fake 时间轴和校验 Gizmo。
- SceneId、Build Settings、测试 ID 和引用迁移记录。
- 场景独立 PlayMode 测试、截图和性能基线。

## 测试要求

- 新 SceneId 可加载，旧误拼写路径不再被运行时引用，GUID/序列化引用完整。
- 玩家固定在卧姿射击点；人工移动、传送和人工转向均不可用。
- UI、HUD、枪 Anchor 独立存在且不需要真实 UI/枪 Prefab。
- 路线长度、端点顺序、目标初始位置和复位位置符合合同。
- Fake 进度 0、0.5、1 能准确映射左右端点与中点；端点状态可显示但不自行决定禁射。
- Collider/LayerMask 能区分目标命中和环境命中。
- 场景单独运行时 Console 0 error；warning 清零或记录原因。

## 验收标准

- 不加载 UI 和玩法实现即可独立打开、驱动、测试和评审移动靶场。
- 场景中没有倒计时、速度选择、禁射判定、弹药、统计、评级和结算业务逻辑。
- 场景仅为固定白天效果，不存在昼夜系统、夜视或夜间资源。
- 无玩家行走区域或 Locomotion 入口，真实 HMD/双手追踪仍保留。

## 联调契约（非实现依赖）

- 玩法只需向视觉驱动提供归一化路线状态、开火许可和逐发 ShotId；场景可完全用 Fake 开发。
- UI 只通过 Anchor 挂接；场景不引用 UI Prefab、Presenter 或页面 ID 内部结构。
- 阶段审核节点 D 组合真实适配器，不改变场景对外绑定语义。

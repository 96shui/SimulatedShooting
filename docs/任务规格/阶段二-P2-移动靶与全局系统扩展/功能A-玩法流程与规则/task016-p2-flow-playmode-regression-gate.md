# task016 P2 端到端 PlayMode 与 P1 回归门禁

## 负责人

功能A-玩法流程与规则

## 目标

建立可在 Unity Editor 无 VR 设备环境运行的 P2 端到端 PlayMode 测试与回归门禁，证明移动靶、武器库和设置三个交付切片能通过同一套路由、Session、事件、输入、武器/弹药、HUD 和场景绑定协同运行，并证明 P2 扩展没有破坏 P1 100m 射校闭环。

本任务是 P2 UI 和场景最终收口前的联调门禁。测试失败必须能定位到 UI、场景、功能A或功能B责任边界；不得在测试中复制业务规则或用直接改内部字段的方式绕过真实命令链。

## 交付内容

### 测试夹具

- P2 PlayMode 测试场景或可重复构建的测试夹具，使用生产组合根和可注入适配器。
- 复用 task001 的：
  - 无 VR 输入、头部/双手姿态和枪线替身。
  - 手动时间源。
  - 固定路线配置。
  - 可分别控制两发命中的目标命中替身。
  - 内存/失败设置持久化。
  - 设置运行时预览替身。
  - 稳定测试 ID 查找器与事件记录器。
- 测试只通过公开 UI 事件、服务命令、输入适配、时间推进和场景绑定驱动流程，不直接写服务私有状态。
- 每个测试输出当前 ScreenId、SessionId、SessionState、MovingTarget Phase、Ammo、BurstCount、HitCount、HUD Key、事件序列和失败责任边界。

### 白天移动靶端到端

- 从主菜单或训练模式选择进入移动靶设置。
- 验证默认白天、3/4/5m/s 和默认 4m/s。
- 点击开始只创建一个共享 Session，进入 `MovingTargetDayHud` 和 3 秒等待。
- 等待期间注入扳机，验证无弹药消耗、无点射记录、无射击表现事件。
- 快进到右到左移动，使用无 VR 双手持枪/枪线替身完成 5 次点射。
- 每次点射恰好产生两发射击结果、一次点射记录和 2 发弹药消耗。
- 至少一次点射覆盖 0 发命中、一次覆盖 1 发命中、一次覆盖 2 发命中。
- 左端停留 2 秒期间再次输入，验证弹药、命中、点射节奏和反馈均不变化。
- 返回右端后只进入一次结算，显示 10 发消耗、5 条记录、时间点、昼夜、速度和服务评级。

### 夜晚移动靶端到端

- 切换夜晚后只显示 2/2.5/3m/s，选择 2.5m/s。
- 进入 `MovingTargetNightHud`，验证 Night HudType 和微光镜状态。
- 目标左到右阶段显示正确方向和端点标识数据。
- 端点停留输入仍在弹药/射击反馈前被拦截。
- 完成后结果保留 Night、2.5m/s、逐次记录和正确评级。

### 可控评级与结算

- 参数化服务/集成测试至少覆盖命中 0、2、3、4、5、8：
  - 0、2：不及格。
  - 3：及格。
  - 4：良好。
  - 5、8：优秀。
- PlayMode 完整页面流至少覆盖一个优秀结果和一个不及格结果。
- 另覆盖未射击或只完成 1-4 次点射后路线结束：结算显示实际 0-8 发消耗、实际 0-4 条记录，其余固定槽位为“未使用”，不得伪造时间、位置或命中。
- 重新训练固定返回移动靶设置页，旧 Session、HUD 和点射记录不残留。
- 返回模式选择保存最近评级摘要；持久化失败时显示/返回明确失败，不伪造成功。

### 武器库端到端

- 主菜单打开武器库，公开列表恰好显示四把 BDD 武器，训练专用武器不出现在墙上。
- 默认高亮服务返回的当前已装备武器。
- 依次选择四把武器，属性字段来自 `WeaponDefinitionDto`，选择预览不改变已装备状态。
- 点击装备后才发布 `WeaponChangedEvent` 并更新装备。
- 返回未装备不改变当前武器，并返回正确 ReturnToScreen。
- 在不适用模式上下文选择武器时显示限制并禁用或拒绝装备。

### 设置端到端

- 主菜单进入设置，全部字段来自 `ISettingsService.Load/GetPending`。
- 修改枚举、开关和 Slider 后，Pending 与运行时预览替身同步，已保存值未变。
- 应用后重开设置，显示保存值。
- 恢复默认只改变 Pending 和预览；未应用返回后恢复旧保存值。
- 保存失败保留 Pending、显示失败且不发布正式设置事件。
- 从移动靶训练暂停叠层进入设置并返回，Screen 返回暂停层，原 SessionId、阶段、弹药和点射记录不丢失。

### P1 回归

- 复跑 P1 task014 的第 1 轮优秀和 3 轮不及格完整无 VR 流程。
- 验证 P1 HUD Provider 的稳定 Key、3 发一轮弹药、武器 ID、弹着分析和评级不因 P2 Provider/武器目录/设置服务改变。
- P1 有效/无效射击、换弹、切肩、Busy 防重入和唯一 Camera/AudioListener 的既有 PlayMode 用例全部通过。

## 错误与事件门禁

测试至少覆盖并验证无副作用：

- `InvalidInput`：非法昼夜速度、非法设置值、非法武器模式。
- `InvalidState`：等待/端点点射、第 6 次点射、未完成请求结算、无双手持枪开火。
- `NotFound`：未知 Session、武器、结果或路由目标。
- `Busy`：快速重复开始、场景加载中重复导航、重复换弹。
- `ResourceUnavailable`：移动靶路线/目标/微光/场景绑定缺失。
- `PersistenceFailed`：设置保存和最近评级摘要保存失败。
- 失败命令不得发布成功事件、消耗弹药、增加命中、产生后坐力/VFX 或切换到成功页面。

## 不包含

- 不新增或修改 UI 视觉、布局、Prefab、TMP 文本或动画。
- 不创建移动靶场、武器墙、灯光、材质、后处理或微光镜视觉。
- 不实现或调参武器抓取、点射、后坐力、弹道、触觉、VFX 或音效。
- 不修复测试发现的其他负责范围实现；失败报告应交回对应任务处理。
- 不把测试夹具中的假对象或固定命中数据带入生产构建。

## 联调说明

- 与 UI 联调：只按稳定测试 ID 点击和读取；缺 ID、DTO 映射或 Busy 状态归 UI 任务。
- 与 场景联调：只通过场景绑定查找路线、目标、昼夜根、微光镜、武器墙和 HUD 锚点；缺绑定或视觉状态归场景任务。
- 与 功能B 联调：输入替身、两发点射、统一弹药、逐发命中、武器装备和设置运行时适配归功能B。
- 与 功能A 自检：路由、Session、设置、状态机、HUD、结算、摘要和事件幂等归本目录任务。

## 测试要求

- 所有核心 PlayMode 测试必须在无 VR 设备环境运行，不访问真实玩家配置，不依赖真实随机数或真实帧率。
- 时间推进使用手动时间源，不用长时间 `WaitForSeconds` 等待完整路线。
- 命中结果由逐发可控替身提供，但必须通过与生产相同的点射协调接口进入服务。
- 测试方法名或 TestCase 描述包含 BDD 文件编号和场景名。
- 全量运行：
  - P2 新增 EditMode。
  - P2 新增 PlayMode。
  - P1 现有全量 EditMode/PlayMode。
- 保存 Unity 版本、提交/工作区基线、测试总数、通过/失败/忽略数和结果文件位置。
- 不允许只运行筛选后的成功用例后宣称门禁通过。

## VR 实机验收清单

自动化门禁通过后，记录以下手工验收；未实际执行的项目必须标为“待验收”：

- 主菜单在 HMD 中可读，左右手 UI 射线可进入移动靶、武器库和设置。
- 白天训练可完成 3 秒等待、右到左、左端停留、左到右和结算。
- 夜晚微光镜可用且 HUD 文字清晰，不因后处理无法辨认目标或端点。
- 一次真实扳机点射对应两发反馈和 2 发弹药消耗；端点停留扳机无弹药/后坐力/枪口焰/音效。
- 武器库四把武器可选择预览并装备，返回行为正确。
- 设置预览可观察，返回不保存会回滚；训练中返回设置后原 Session 保留。
- P1 主菜单、拾枪、双手持枪、单发射击和 100m 结算仍正常。
- 全程只有一个活动玩家 Camera 和一个 `AudioListener`；若使用微光 RenderTexture，辅助瞄具 Camera 不超过 1 个、具有稳定 ID、不得携带监听器，且 HMD/Origin 姿态未被武器、设置或微光镜逻辑改写。
- 记录设备型号、OpenXR Runtime、连接方式、刷新率、日期和验收人。

## 验收标准

- 白天、夜晚、武器库、设置和 P1 回归均有无 VR 自动化证据。
- 移动靶完整流程中 10 发、5 次点射、端点禁射、逐发命中、评级和结算均来自服务 DTO/事件。
- 所有错误分支无业务副作用，失败信息能定位责任边界。
- P1 全量测试与 task014 两条端到端结果继续通过。
- 自动化结果和 VR 实机清单已记录；VR 未执行时不得将 P2 标记为完成，只能标记自动化通过/待实机验收。

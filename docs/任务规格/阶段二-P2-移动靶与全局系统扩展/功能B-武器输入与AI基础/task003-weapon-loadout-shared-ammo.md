# task003 武器目录、装备状态与跨模式弹药复用

## 负责人

功能B-武器输入与AI基础

## 目标

## BDD 场景追溯

- `09-移动靶白天HUD.feature.md`：`每次点射消耗两发弹`（本任务只提供一次原子消耗 2 发的弹药端口，点射阶段门禁由 task004/task006 负责）。
- `13-武器库武器墙.feature.md`：`默认显示当前已装备武器`、`选择武器后刷新属性`、`装备选中的武器`、`返回上一界面`、`不适用场景的武器提示`。其中 `装备选中的武器` 在 P2 只验收保存 Loadout、发布事件及后续场景可查询；堑壕/城镇实际生成由 task001 拆分为 P3 验收。

## 交付内容

- 完善 `IWeaponService`、`WeaponDefinitionDto` 和当前装备状态：
  - 目录提供 19-1 自动步枪、95-1 自动步枪、QBS-09 霰弹枪和 QJB-201 班用机枪的接口文档字段。
  - 选择预览与正式装备分离；只有 `Equip` 成功才发布 `WeaponChangedEvent`。
  - 按 `ApplicableModes` 拒绝不适用模式，返回 `InvalidInput`。
  - 返回武器库前后保持已装备武器；不把 UI 高亮当作装备权威。
- 完善共用 `IAmmoService`：
  - 以 `SessionId` 隔离 100m 与移动靶弹药状态。
  - P1 现有 3 发/轮规则和换弹行为保持不变。
  - 移动靶 Session 初始化为 10 发可用弹药，并提供一次原子 `TryConsume(2)` 或 task001 冻结的等效端口。
  - 弹药服务只校验 Session、换弹状态和余额，不感知路线阶段或点射次数；task006 是唯一点射协调器，负责在调用弹药端口前完成 task004 的等待、端点、完成和 5 次上限门禁。
  - 余额不足时原子消耗失败且快照不变；成功时只发布一次 `AmmoChangedEvent`，供 HUD 聚合而不是由 View 自行扣数。
- 在 task001 冻结的接口中明确移动靶训练武器 ID 或按模式覆盖弹药配置；不得直接把 P1 的 3/6 弹药配置误用于移动靶。
- 保持现有 P1 `IWeaponControlService`、射击快照和输入接口兼容。

## 不包含

- 不实现武器库 UI 或武器墙 GameObject。
- 不实现移动靶运动、评级、HUD 文本或夜晚视觉效果。
- 不要求四类武器在 P2 具备完整战斗弹道、动画或真实 VR 操作；堑壕/城镇生成由 P3 接入。
- 不实现真实弹匣插拔、拉机柄、保险或卡弹。

## 联调说明

- 与 功能A 联调：Session 创建时传入训练模式、武器和移动靶弹药配置；task004/task006 的禁射判定必须先于调用本任务的弹药端口。
- 与 UI 联调：提供武器列表、预览、已装备武器和 `AmmoDto`，UI 不缓存第二份业务状态。
- 与 场景 联调：武器墙展示只读取定义和装备事件；P2 训练场复用 P1 训练主武器 Prefab。

## 测试要求

- EditMode 单元测试：
  - 四类武器定义、容量、后坐力等级和适用模式与接口文档一致。
  - `SelectPreview` 不改变已装备武器，`Equip` 成功后才改变并发布一次事件。
  - 不存在武器返回 `NotFound`，模式不适用返回 `InvalidInput`。
  - 不同 Session 弹药互不串扰，P1 回归仍保持原弹药规则。
  - 移动靶从 10 发开始，连续五次原子 `TryConsume(2)` 按 10→8→6→4→2→0 变化，每次只发布一个成功事件。
  - 余额不足 2 发时原子失败、不扣弹、不发布成功弹药事件。
  - 等待、端点和第 6 次点射的门禁测试归 task004/task006；本任务只验证协调器拒绝前没有发生弹药端口调用。
- 测试名称或说明必须引用上述 BDD 场景。

- 移动靶和 P1 共用同一个弹药服务与事件模型，没有 View 侧扣弹或回滚。
- P1 武器控制与现有测试保持通过。
- EditMode 测试全部通过。

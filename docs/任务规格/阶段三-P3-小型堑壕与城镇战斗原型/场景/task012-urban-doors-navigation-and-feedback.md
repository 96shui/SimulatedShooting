## 实现内容

### 1. 数据与入口

烘焙街道、入口、楼梯和三层房间 NavMesh；处理门开合时的通行障碍，保证可搜索房间与队友跟随路径可达。

### 2. 状态与交互

为入口、门、检查区配置可替换交互适配器，输出 ID/范围/确认事实；收到服务认可的门状态后才驱动门动画/碰撞，不在动画事件里增加搜索进度。

### 3. 服务与适配

复用敌人/队友 Prefab 与命中反馈；支持街道 1–2、建筑 3–6 敌人的视觉实例和尸体保留，真实生成数量由服务决定。

### 4. 边界与幂等

完善各层地图资源、门口提示挂点、射线/Collider/LayerMask、基本墙体遮挡；保持 HUD 与 UI 锚点可独立绑定。

### 5. 事件与生命周期

完善适度写实材质/灯光和内外亮度过渡，记录最大角色/尸体情况下的 CPU/GPU/GC、阴影和加载数据；设备/场景/采样方式必须可追溯。

### 6. 交付与兼容

重试和卸载恢复房门/碰撞/角色/音效/导航状态，保留地图资产与稳定 ID；避免每次重试重复生成永久对象。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- PlayMode：入口范围与射线确认、门状态只响应被接受的服务输出、重复门事件幂等。
- PlayMode：逐层进出、开门后可通行、队友上下楼，假导航失败可反馈；基本墙体阻挡枪线。
- PlayMode：敌人死亡尸体保留、本局最大角色配置、连续重试/卸载无旧门状态/角色残留或 Missing Script。
- 手工 VR：楼梯与转角舒适度、室内 HUD 可读性、队友/武器穿插、最坏视角性能；无设备标记待验。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 验收标准

- 房门/房间/入口 ID 与 task009 配置一致，场景仅提供物理与表现，搜索规则仍由服务决定。
- 可用 Fixture 完成街道→各层→房间→死亡表现→重试，交付可重复性能采样路径。
- 交付物、测试和证据齐全；新增错误不得遗留，已知警告逐项说明。
- 对应审核节点通过后才可标记 `[x]`；只有代码、Fake 演示或自测报告时标记 `[~]`。
- 必须实机确认的交互/舒适度项目未测时保留“待验”，阶段收口由节点 D 单独判定。

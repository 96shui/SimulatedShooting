## 实现内容

### 1. 数据与入口

创建/补齐 Assets/Scenes/UrbanScene.unity：一条街、一栋三层楼、总计 3–5 个房间（不是每层 3–5 个）；楼梯连通各层且可返回街道。

### 2. 状态与交互

提供玩家/两队友出生、武器、HUD/结算锚点和 BuildingEntranceId；FloorId、RoomId、门、搜索区与地图配置逐项对应。

### 3. 服务与适配

布置街道 1–2 名、建筑 3–6 名敌人的候选点，建筑点覆盖楼道拐角/房间；敌人数量选择和随机分布留给服务。

### 4. 边界与幂等

输出街道底图、1F/2F/3F 楼层边界和缩略图资源键，提供世界坐标映射配置以供玩法聚合地图 DTO。

### 5. 事件与生命周期

建立门口/入口范围、房间检查区和基础环境 Collider；触发器只报进入/退出/交互事实，不自行标记房间已搜索。

### 6. 交付与兼容

校验入口、楼层、房间 ID 唯一，出生和候选点不在墙内；楼梯、门洞尺寸适合三人队列及武器碰撞。

## 交付物

- 街道及三层平面图资源、UI/角色/武器锚点。
- 场景 EditMode/PlayMode、无 VR 巡检路径与平面截图。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- EditMode：恰好三层、总计 3–5 房间、入口/门/搜索区完整、唯一 ID 与配置一致。
- PlayMode：从街道经入口上到各层再返回；出生、门洞、楼梯和全部检查区域可达。
- PlayMode：Fake 场景事实输入能标识当前入口/楼层/房间；无 Missing Script 或对真实 UI/玩法硬引用。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 验收标准

- 地图规模和 ID 明确，可供房间/搜索/导航 Fixture 独立运行。
- 场景不自动创建战斗 Session，不决定敌人数、房间完成度或胜负。
- 交付物、测试和证据齐全；新增错误不得遗留，已知警告逐项说明。
- 对应审核节点通过后才可标记 `[x]`；只有代码、Fake 演示或自测报告时标记 `[~]`。
- 必须实机确认的交互/舒适度项目未测时保留“待验”，阶段收口由节点 D 单独判定。

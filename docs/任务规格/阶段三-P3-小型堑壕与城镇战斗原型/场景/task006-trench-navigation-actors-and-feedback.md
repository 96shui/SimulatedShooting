## 实现内容

### 1. 数据与入口

烘焙并校验堑壕可行走 NavMesh，覆盖玩家路线、两名队友跟随和所有允许生成位置；拐角/窄道不得把队友初始位置放入墙体。

### 2. 状态与交互

建立敌人/队友 Prefab 绑定：角色 ID、命中 Collider、感知射线源、枪口/音源、动画/尸体根、导航执行器；实体状态来自服务快照。

### 3. 服务与适配

导航执行器只执行目的地/朝向并回报到达或失败，不决定三人队形或敌人攻击时机；感知适配器上报视线与遮挡事实。

### 4. 边界与幂等

敌人有效命中播放中弹音效，死亡后保留尸体视觉并停止攻击/导航表现；按唯一事件 ID 去重；尸体持续到退出/重试，卸载后释放。

### 5. 事件与生命周期

完善简化无人机/投影演示、昼间环境、灯光与必要材质；以可读性、碰撞尺度和 VR 流畅为优先，控制尸体/阴影/音源开销。

### 6. 交付与兼容

接入武器和 UI 锚点校验；输出任务场景的资源/性能初始基线及加载卸载记录，保留 task003 稳定 ID。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- PlayMode：Fake 3–5 敌人/两队友实例映射正确，前后朝向可表达，路径成功/失败均反馈。
- PlayMode：重复命中事件只反馈一次、敌人死亡后尸体不消失、重试卸载旧角色且新局不残留。
- PlayMode：墙体遮挡感知/基本射线，合法候选点在有效导航区，场景切换无 Missing Script/重复相机。
- 手工 VR：拐角转身、队友遮挡、机瞄、尸体密集处帧时；无设备时记录待验，不填写通过。

## 实现内容

### 1. 数据与入口

完整实现 ITrenchService：地图查询/选择、简报预览、开始、搜索节点、击杀登记、完成和失败；简报只预览，StartSession 才创建本局角色状态。

### 2. 状态与交互

按固定种子从有效候选位置生成 3–5 名敌人的数量和偏移；预估区域与真实生成位置分开保存，预览和 HUD 不泄露精确偏移。

### 3. 服务与适配

实现三人纵队：玩家在最前、二号在后朝前、三号最后朝后。队形目标由服务/AI 产生，导航适配器执行；路径失败按冻结策略处理，不把玩家拖动。

### 4. 边界与幂等

将 SearchNode 输入按合法当前会话和节点校验后幂等登记，进度来自节点集合；敌人死亡按唯一 ID 登记，不从场景 GameObject 数量计算。

### 5. 事件与生命周期

实现“全部节点搜索 + 全部敌人消灭 + 玩家存活”胜利与死亡失败；同一更新批次胜负竞争按 task001 冻结优先级处理，只生成一次不可变结果。

### 6. 交付与兼容

输出 TrenchSessionDto、TrenchResultDto、SquadStatusDto、HudDto/MiniMapDto；统一计时、弹药快照、敌情预估与死亡标记。

### 7. 回归与收口

重试清空节点、敌人、队伍、计时和订阅；保留地图/训练武器选择并回到简报/准备，不复用旧 SessionId。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- EditMode：3/5 敌人数边界、固定种子复现、非法地图/节点/敌人/会话；重复搜索/击杀不重复累计。
- EditMode：只搜索完成或只清敌不得胜利；死亡失败保留部分统计；完成后旧事件不改结果。
- EditMode：队形顺序/朝向、路径失败、两队友 DTO 与空指令列表；未开放命令不可假成功。
- PlayMode：Fake 场景输入驱动简报→开战→部分搜索→清敌→胜利/失败→重试，HUD/结果事件来源一致。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

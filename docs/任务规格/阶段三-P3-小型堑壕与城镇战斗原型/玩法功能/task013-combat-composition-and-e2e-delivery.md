## 实现内容

### 1. 数据与入口

在组合根注册 Trench/Urban 服务、共用战斗/队形、HUD、输入、场景事实适配器和 UI Presenter；真实依赖只在应用装配边界汇合。

### 2. 状态与交互

接通主菜单/模式选择→堑壕地图→简报→战斗→结果，以及城镇地图→街道→建筑→结果；加载期间统一 Busy，失败保留可恢复页面。

### 3. 服务与适配

实现场景加载、任务创建、武器/队友初始化的明确时序；不得在简报预览重复创建角色或在进入建筑时丢掉街道 Session。

### 4. 边界与幂等

统一成功/失败结果显示、重试、取消和返回；停止攻击/输入/计时，退订事件，清理场景实体和旧 Session 回调，确保再次进场状态正确。

### 5. 事件与生命周期

按 BDD 返回主菜单时保存最近结果摘要；复用本地存储边界并处理 PersistenceFailed，不扩张成完整历史档案系统。

### 6. 交付与兼容

提供 Editor/无 VR 实际演示路径和自动化 E2E，真实 UI/场景/服务至少各跑一次胜利、失败、重试、退出；不能仅凭 Fake E2E 标记集成完成。

### 7. 回归与收口

执行 P1/P2 回归。已有失败须登记基线、责任人和复验结果，不用删除/放宽断言掩盖；P2 未收口不能在 P3 报告中被改成已通过。

## 交付物

- 应用组合根、模式/场景路由适配、生命周期与摘要保存接入。
- 两种模式真实无 VR E2E、回归结果文件与日志。
- 逐步演示说明、异常复位说明、交付记录及交给审核节点 C/D 的候选版本。

交付记录另建 `task013-交付记录.md`，至少包括：实际变更路径、BDD/接口/测试映射、测试命令与结果文件、提交号、使用的替身、联调状态、已知问题及 VR 待验项。交付记录不另占任务编号。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- PlayMode：堑壕真实地图/简报→搜索与清敌→胜利；受伤死亡失败；重试/返回再进，数据无串局。
- PlayMode：城镇街道→入口→开门/检查所有房间→清敌胜利；中途死亡结果保留；街道状态跨阶段保留。
- PlayMode：重复开始、加载失败、取消、快速切模式、存储失败、连续三次重试与旧事件隔离。
- 回归：P1 固定卧姿/取枪显隐/单发/三轮评级，P2 速度/倒计时/路线禁射/两发与长按/结算；记录测试命令、Unity 版本、提交号和结果路径。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 验收标准

- 两种真实场景都能通过同一输入适配在无设备环境完成胜利/失败/重试/返回流程。
- 提交可审查的集成证据，遗留失败与 VR 待验明确列出；本 task 不替代审核负责人签署阶段通过。
- 交付物、测试和证据齐全；新增错误不得遗留，已知警告逐项说明。
- 对应审核节点通过后才可标记 `[x]`；只有代码、Fake 演示或自测报告时标记 `[~]`。
- 必须实机确认的交互/舒适度项目未测时保留“待验”，阶段收口由节点 D 单独判定。

## 联调对象与边界

- 三条生产线所有 P3 task；接口偏差退回对应 task 或先补文档，不能在组合根塞业务补丁。
- 审核测试与优化：提供候选提交号、自动化结果、VR 演示步骤和性能路径，由其独立执行节点 C/D。

不接管 UI/场景主体制作、不设独立服务器、不替审核负责人宣告验收通过；不做 Later 能力。

## 无 VR 与 VR 交付

- 无 VR：交付可复现的输入/DTO/场景 Fixture 操作步骤，不能要求人工改 Hierarchy 才能正常启动。
- VR：与本任务有关的移动、自然机瞄、UI 可读性、交互可达性或队友遮挡，写明设备、步骤、预期和结果；未涉及设备体验的纯规则任务注明不适用并给出联调入口。

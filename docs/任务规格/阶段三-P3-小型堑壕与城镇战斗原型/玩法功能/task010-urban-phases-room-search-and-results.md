## 实现内容

### 1. 数据与入口

实现 IUrbanService 地图查询/选择、StartSession、EnterBuilding、OpenRoomDoor、MarkRoomSearched、RegisterEnemyKilled、CompleteIfReady、FailByPlayerDeath；ObserveRoom 按冻结的 Later 支持策略返回一致结果。

### 2. 状态与交互

固定种子生成街道 1–2 敌人、建筑 3–6 敌人并赋予稳定归属 ID；三层楼总计 3–5 房间；不得把进入建筑当作新 Session 重置街道数据。

### 3. 服务与适配

实现 Street/Building/Results 阶段，入口 ID 与玩家范围事实双校验；街道未清除时按已冻结规则处理并保留剩余敌人。

### 4. 边界与幂等

房间 Unsearched→Searching→Searched：合法开门进入 Searching；检查完成并满足房间清敌条件才标记 Searched。重复开门/搜索/击杀幂等；空房也要检查。

### 5. 事件与生命周期

维护 StreetCleared、楼层/房间状态、街道/建筑击杀分项、队友、血量/弹药与小地图；通过命令/查询/事件输出，不读场景激活状态猜规则。

### 6. 交付与兼容

只有街道清敌、建筑全部房间搜索且全部敌人清除、玩家存活时才能胜利；死亡中途失败保存部分进度；结束后不可再变更结果。

### 7. 回归与收口

输出三层结果地图和 UrbanResultDto；重试重建敌人/房门/房间/队伍/弹药/计时，清理旧 Session 和事件订阅。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- EditMode：敌人数上下限、三层/房间数量校验、固定种子一致性、非法地图/入口/房间/敌人/会话。
- EditMode：范围外禁止进入、街道未清除行为；开门不等于已搜索、空房需检查、有活敌不得完成搜索、重复请求不增量。
- EditMode：只搜索或只击杀不能胜利，街道残敌阻止胜利，玩家死亡保留部分结果，同批次胜负按冻结优先级只结算一次。
- PlayMode：Fake 入口/门/搜索输入走完 Street→Building→Results；失败、重试、返回与旧会话隔离。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 实现内容

### 1. 数据与入口

按 draw.io p12/p14 制作 TrenchMapSelection、TrenchBriefing 两个页面；生产仅要求地图 A，地图 B 依冻结范围隐藏或禁用，不允许进入不存在的关卡。

### 2. 状态与交互

地图名称、复杂度、3–5 人敌情范围、搜索/清敌/死亡条件来自 TrenchMapDto 与提示数据；选择只提交 SelectMap，不生成敌人。

### 3. 服务与适配

简报展示 PlannedSquad、ProjectedMap 和敌情预估；无人机动画使用可替换演示端口，简化过场与真实资源都不应影响玩法状态。

### 4. 边界与幂等

实现查看地图/返回简报、返回地图选择、开始进入和加载中状态；开始成功才由路由切换 HUD，失败保持本页并显示服务消息。

### 5. 事件与生命周期

实现按钮防重复和 Presenter 订阅释放；接收旧 Session/旧请求结果时不得跳到过期页面。

### 6. 交付与兼容

提供 Screen_TrenchMapSelection、Screen_TrenchBriefing；Button_TrenchMapSelection_SelectMap/Back，Button_TrenchBriefing_Start/ViewMap/Back；地图和小队文本按文档 11 提供测试 ID。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- PlayMode：默认地图、非法/不可用地图、查看/收回投影、返回不创建 Session、开始成功/失败/Busy、防重复提交。
- PlayMode：简报阶段不进入战斗；只有一次成功开始命令才切 HUD；销毁/重建不重复订阅。
- EditMode：如新增独立格式化逻辑，验证空地图、空队伍和未知枚举的安全显示。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 验收标准

- 空白测试场景可走完地图→简报→模拟 HUD 路由；View 不持有 TrenchService、敌人组件或场景硬引用。
- 未开战时 UI 不触发生成和伤害；页面布局与 p12/p14 一致，数据均可被 Fake DTO 改变。
- 交付物、测试和证据齐全；新增错误不得遗留，已知警告逐项说明。
- 对应审核节点通过后才可标记 `[x]`；只有代码、Fake 演示或自测报告时标记 `[~]`。
- 必须实机确认的交互/舒适度项目未测时保留“待验”，阶段收口由节点 D 单独判定。

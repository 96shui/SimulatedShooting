## 实现内容

### 1. 数据与入口

制作 Screen_UrbanMapSelection、Screen_UrbanStreetHud；生产只开放已交付地图 A，地图 B 遵循冻结的不可用展示规则。

### 2. 状态与交互

显示街道 1–2 人、建筑 3–6 人、三层楼与搜索目标；实际配置与地图选择数据来自服务，UI 不生成角色。

### 3. 服务与适配

复用战斗 HUD/小地图呈现玩家、两队友、敌情预估、入口、30/120 弹药、血量/姿态/肩侧与任务状态。

### 4. 边界与幂等

入口提示的可见/可交互状态由服务提示 DTO 驱动；确认只转发 EnterBuilding，范围判断由服务及场景事实适配器负责。

### 5. 事件与生命周期

按 task001 冻结口径显示街道未清除风险；未成功进入时保持 Street HUD，成功事件才进入 Building HUD，保留街道状态。

### 6. 交付与兼容

实现加载/Busy、非法入口、失败重试、防重复命令、退出退订；稳定 ID 包括 Button_UrbanMapSelection_SelectMap/Back、Button_UrbanStreetHud_EnterBuilding 和 Hud_UrbanStreet_*。

交付记录另建 `task008-交付记录.md`，至少包括：实际变更路径、BDD/接口/测试映射、测试命令与结果文件、提交号、使用的替身、联调状态、已知问题及 VR 待验项。交付记录不另占任务编号。

## 测试要求

先补或更新本任务的自动化测试，再实现业务/适配逻辑。以下均为待新增或待更新的测试要求，不代表当前已有通过结果。

- PlayMode：默认地图、返回无 Session、开始错误/Busy、街道 HUD 字段随 DTO 刷新。
- PlayMode：范围外入口不可提交有效进入，范围内成功切页；错误仍留原页，街道未清除风险与冻结规则一致。
- PlayMode：街道已清除状态在切建筑时保持；入口提示不遮挡 HUD，销毁/重进不重复触发命令。

测试资产应放入现有适用的 EditMode/PlayMode 程序集，按功能选择 `Assets/VRShooting/Tests/` 或 `Assets/SimulatedShooting/Tests/`；无需为每个 task 再建一套测试框架。VR 相关功能必须保留无设备测试路径。

## 验收标准

- 以空白场景 Fixture 即可验收地图→街道→建筑 HUD 路由；UI 无具体入口 Collider/敌人组件引用。
- 状态转换和入口许可均以服务返回为准，不能点击按钮就强制加载楼层。
- 交付物、测试和证据齐全；新增错误不得遗留，已知警告逐项说明。
- 对应审核节点通过后才可标记 `[x]`；只有代码、Fake 演示或自测报告时标记 `[~]`。
- 必须实机确认的交互/舒适度项目未测时保留“待验”，阶段收口由节点 D 单独判定。

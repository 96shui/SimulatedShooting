# 05 100m射击HUD

来源：draw.io 页面 `p05 05 100m射击HUD`

阶段：P1。

## 功能

作为玩家，我希望在第一人称射击 HUD 中完成每轮 3 发射击，并实时看到轮次、距离、弹数、稳定度和弹着记录。

```gherkin
# language: zh-CN
功能: 100m 射击 HUD

  背景:
    假如玩家已开始 100m 精度射校靶
    而且当前轮次为 1/3
    而且本轮剩余弹数为 3/3

  场景: HUD 显示当前训练状态
    当 100m 射击 HUD 加载完成
    那么顶部左侧应显示“轮次 1/3”
    而且顶部中间应显示“距离 100m”
    而且顶部右侧应显示“弹数 3/3”
    而且右侧应显示弹着记录面板
    而且左下应显示稳定度条

  场景: 据枪稳定提示随枪体晃动变化
    假如玩家手持武器晃动低于稳定阈值
    当 HUD 刷新稳定度
    那么稳定度条应显示稳定状态
    而且中心提示应显示“稳定据枪”

  场景: 玩家单发射击后减少弹数
    当玩家扣动扳机完成一次有效射击
    那么本轮剩余弹数应减少 1
    而且弹着记录面板应追加一个命中点
    而且弹着点应由准星、枪体晃动和本局偏移共同计算

  场景: 无 VR 设备时用输入替身完成单发射击
    假如当前使用输入替身或 XR Device Simulator
    当测试输入触发扳机
    那么系统应按同一武器发射流程完成一次有效射击
    而且本轮剩余弹数应减少 1
    而且 HUD 刷新来源应仍然是服务层 DTO 或事件

  场景: 第一人称视角中显示可操作训练步枪
    当 100m 射击 HUD 加载完成
    那么玩家应在第一人称视角中看到训练步枪枪体
    而且训练步枪应包含枪口、后手握把、前手握把和瞄准线参考
    而且 HUD 弹药、可射击状态和肩侧状态应来自武器服务 DTO 或事件

  场景: VR 双手一前一后控制枪线
    假如玩家后手抓住训练步枪后手握把
    而且玩家前手抓住前手握把或护木
    当玩家移动前手控制器
    那么训练步枪枪口方向应随前手位置变化
    而且有效射击方向应来自枪口或瞄准线方向

  场景: 非瞄准模式下头显自由观察
    假如玩家处于非瞄准模式
    当玩家转动 VR 头显或无 VR 调试视角
    那么第一人称观察方向应随头显或调试视角变化
    而且开火方向仍应以当前枪口或瞄准线方向为准

  场景: 瞄准模式下视角对齐枪线
    当玩家进入瞄准模式
    那么画面应呈现沿训练步枪瞄准线观察的机瞄视角
    而且玩家移动双手控制训练步枪时应改变瞄准方向
    而且射击方向、可见弹道和命中计算应使用同一枪线

  场景: 有效射击显示可见弹道和弹着反馈
    当玩家扣动扳机完成一次有效射击
    那么枪口应生成沿枪线飞出的可见弹道或曳光
    而且弹道命中靶面后应显示弹着点或命中反馈
    而且弹着记录面板应追加同一次射击结果

  场景: 按按钮换弹和切换左右肩
    当玩家触发换弹输入
    那么武器应进入按钮换弹流程
    而且 HUD 弹药数据应从弹药服务刷新
    当玩家触发左右肩切换输入
    那么武器射击参考点应切换到另一侧
    而且 HUD 或操作提示应显示当前肩侧

  场景: 本轮 3 发完成后打开弹着分析
    假如玩家已完成本轮第 3 发有效射击
    当弹着记录写入完成
    那么系统应打开“本轮弹着分析”界面
    而且射击输入应临时禁用

  场景: 弹数为 0 时禁止继续射击
    假如本轮剩余弹数为 0
    当玩家继续扣动扳机
    那么系统不应生成新子弹
    而且弹着记录不应新增命中点
```

## Unity 验收点

- P1 允许使用射线或简化弹道完成命中计算，但每次有效射击必须有从枪口发出的可见弹道或曳光表现；后续可替换为更完整的 `Firearm`/`Bullet` 实现。
- 弹着记录不应只由子弹碰撞决定，还应记录射击时刻的准星状态和当前归零偏移。
- 同一套射击、换弹、左右肩切换和瞄准逻辑必须同时支持真实 XR 输入、XR Device Simulator 和无 VR 输入替身。
- 无 VR 设备时，Unity Editor Play Mode 中应能直接看到训练步枪、双手替身控制效果、ADS/机瞄视角、弹道和靶面命中反馈。

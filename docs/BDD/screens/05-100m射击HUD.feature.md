# 05 100m射击HUD

来源：draw.io 页面 `p05 05 100m射击HUD`

阶段：P1。

## 功能

作为玩家，我希望在第一人称射击 HUD 中完成每轮 3 发射击，并实时看到轮次、距离、弹数、稳定度和弹着记录。

```gherkin
# language: zh-CN
功能: 100m 射击 HUD

  背景:
    假如玩家已开始 100m 精度射校靶
    而且当前轮次为 1/3
    而且本轮剩余弹数为 3/3

  场景: HUD 显示当前训练状态
    当 100m 射击 HUD 加载完成
    那么顶部左侧应显示“轮次 1/3”
    而且顶部中间应显示“距离 100m”
    而且顶部右侧应显示“弹数 3/3”
    而且右侧应显示弹着记录面板
    而且左下应显示稳定度条

  场景: 据枪稳定提示随枪体晃动变化
    假如玩家手持武器晃动低于稳定阈值
    当 HUD 刷新稳定度
    那么稳定度条应显示稳定状态
    而且中心提示应显示“稳定据枪”

  场景: 玩家单发射击后减少弹数
    当玩家扣动扳机完成一次有效射击
    那么本轮剩余弹数应减少 1
    而且弹着记录面板应追加一个命中点
    而且弹着点应由准星、枪体晃动和本局偏移共同计算

  场景: 无 VR 设备时用输入替身完成单发射击
    假如当前使用输入替身或 XR Device Simulator
    当测试输入触发扳机
    那么系统应按同一武器发射流程完成一次有效射击
    而且本轮剩余弹数应减少 1
    而且 HUD 刷新来源应仍然是服务层 DTO 或事件

  场景: 第一人称视角中显示可操作训练步枪
    当 100m 射击 HUD 加载完成
    那么玩家应在射击位枪架或武器台上看到训练步枪枪体
    而且训练步枪应包含枪口、后手握把、前手握把和瞄准线参考
    而且训练步枪不应在玩家尚未拾取时绑定到 HMD 相机或任一手柄
    而且 HUD 弹药、可射击状态和肩侧状态应来自武器服务 DTO 或事件

  场景: 右手靠近后握把并按握把键拾取步枪
    假如玩家尚未持有训练步枪
    而且右手直接交互器已进入训练步枪后手握把的近距抓取范围
    那么后握把应出现非遮挡式可拾取提示“按住右手 Grip 拾取”或等效设备图标
    当玩家按住右手 Grip 或项目配置的拾枪 Select 动作
    那么训练步枪应在一个渲染帧内把后手握把对齐到右手抓取姿态
    而且武器状态应变为“右手持枪”
    而且右手虚拟手模型应显示为握住后手握把
    而且应播放一次近距离机械拾枪声
    而且拾取提示应立即隐藏

  场景: 手柄不在后握把附近时不能隔空拾枪
    假如右手直接交互器不在训练步枪后手握把的近距抓取范围
    当玩家按住右手 Grip 或项目配置的拾枪 Select 动作
    那么训练步枪不应移动到玩家手中
    而且武器状态应保持为“在架”或“已掉落”

  场景: 左手抓住前握把后进入双手持枪
    假如玩家已用右手握住训练步枪后手握把
    而且左手直接交互器已进入前手握把或护木的近距抓取范围
    当玩家按住左手 Grip 或项目配置的前手 Select 动作
    那么左手虚拟手模型应对齐前握把
    而且武器状态应变为“左前右后双手持枪”
    而且后手位置应控制枪体基准位置
    当玩家移动前手控制器
    那么训练步枪枪口方向应随前手位置变化
    而且有效射击方向应来自枪口或瞄准线方向

  场景: 双手持枪时右手扳机完成射击
    假如玩家处于“左前右后双手持枪”状态
    而且当前武器允许射击并且弹匣内有弹药
    当右手 Trigger 从释放阈值越过击发阈值
    那么系统应只触发一次有效射击
    而且左手扳机或右手 Grip 不应被解释为击发

  场景: 未形成双手持枪时扳机不产生有效射击
    假如训练步枪仍在枪架、已经掉落或仅由右手握住
    当玩家按动右手 Trigger
    那么系统可以发布带错误码的失败射击结果
    但是不得消耗弹药、生成曳光、记录弹着、施加后坐力或发送击发触觉

  场景: 松开前手或后手结束对应持枪状态
    假如玩家处于“左前右后双手持枪”状态
    当玩家松开左手 Grip
    那么训练步枪应回到“右手持枪”状态并禁止有效射击
    当玩家随后松开右手 Grip
    那么前手选择应被同时取消
    而且训练步枪应进入“已掉落”状态并恢复场景物理

  场景: 非瞄准模式下头显自由观察
    假如玩家处于非瞄准模式
    当玩家转动 VR 头显或无 VR 调试视角
    那么第一人称观察方向应随头显或调试视角变化
    而且开火方向仍应以当前枪口或瞄准线方向为准

  场景: 真实 VR 中通过头部和枪体姿态自然完成机瞄
    假如玩家正在使用真实 HMD 和双手控制器
    当玩家把机械瞄具移动到眼前并主动对齐照门、准星与目标
    那么画面应保持 HMD 原生双目跟踪视角
    而且系统不得把 HMD 相机吸附到枪线、修改 XR 投影视场角或切换到非 HMD 代理相机
    而且玩家移动头部只改变观察位置，移动双手才改变枪体和有效射击方向
    而且射击方向、可见弹道和命中计算应使用同一枪口或瞄准线

  场景: 无 VR 调试路径使用 ADS 代理
    假如当前未运行 XR 设备
    当玩家触发瞄准输入
    那么无 VR 相机可平滑进入沿训练步枪瞄准线观察的 ADS 代理视角
    而且不得改变真实 VR 路径的 HMD 相机规则

  场景: XR 运行时只启用一套玩家视角
    假如 OpenXR 已成功启动并检测到 HMD
    当 100m 靶场进入可操作状态
    那么 XR Origin 和 HMD 相机应自动启用
    而且无 VR 相机及其 AudioListener 应自动禁用
    而且场景中不得同时存在两个活动玩家相机或两个活动 AudioListener

  场景: VR 靶场使用真实地面高度并提供舒适的 UI 与拾枪位置
    假如 OpenXR 已启动并使用 HMD 或 XR Device Simulator
    当玩家进入 100m 靶场射击位
    那么 XR Origin 应使用 Floor Tracking Origin 且不得再叠加固定站立眼高
    而且初始视点与地面的高度差应由 HMD 或输入替身的真实跟踪姿态决定
    而且 World Space UI 应在跟踪姿态稳定后重新摆放到水平视线略下方
    而且 World Space UI 应位于玩家前方 1.2m 至 1.5m、足够大且下沿不得低于地面 0.10m
    而且初始步枪应位于玩家右前方的自然伸手范围和腰胸之间的舒适高度
    而且武器、UI 和后坐力逻辑不得直接平移 HMD Camera 或 XR Origin 来修正高度

  场景: 控制器跟踪暂时丢失时禁止击发
    假如玩家已双手持枪
    当右手或左手控制器的有效跟踪丢失超过允许缓冲时间
    那么武器应立即变为不可射击
    而且枪体不得瞬移到世界原点或飞离玩家
    当双手跟踪恢复且 Grip 仍保持时
    那么系统可重新建立对应持枪状态

  场景: 有效射击显示可见弹道和弹着反馈
    当玩家扣动扳机完成一次有效射击
    那么枪口应播放一次空间化步枪击发声并显示短促枪口焰
    而且枪口应生成沿枪线快速移动的弹体或曳光，而不是持续显示整条激光线
    而且弹体飞行时应播放短促的弹丸破空声
    而且弹道命中靶面后应显示弹着点或命中反馈
    而且命中靶面时应在同一命中点播放材质匹配的撞击声和短促火花或碎屑
    而且弹着记录面板应追加同一次射击结果
    而且枪口焰、弹道终点、命中反馈、声音和弹着记录应使用同一次有效射击结果

  场景: 虚拟手使用手部网格并在持枪时切换握持姿势
    假如左右控制器均处于有效跟踪状态
    当玩家尚未抓取训练步枪
    那么左右虚拟手应显示为自然放松的手部网格而不是立方体占位
    而且虚拟手应随对应控制器一比一跟踪
    当右手拾取后握把且左手选择前握把
    那么右手中指、无名指和小指应自然收紧并包住后握把
    而且右手食指应从掌指关节转向扳机并保持相对伸直，不应与其余手指一起卷成握拳姿势
    而且右手拇指应从握把另一侧形成对向支撑
    而且右手手腕纵轴应近似竖直并对齐后握把，不应平行贴在枪托或穿过枪体
    而且左手掌心应朝上，以拇指和食指之间保持开放的虎口并与掌根共同托住护木下方
    而且左手拇指与四指应分别位于护木两侧，四指仅小幅向上自然弯曲，不应越过顶部导轨或卷成闭合拳圈
    而且左手不应以手背朝上的姿态压在护木上
    而且除手指围绕握把或护木的预期接触外，左右手网格不应与枪体出现明显穿模
    而且只允许调整虚拟手网格，不得反向移动控制器、HMD 或 XR Origin

  场景: 玩家移动和停止时播放对应脚步
    假如玩家处于可操作的 100m 靶场
    当玩家通过连续移动或真实位移在地面上行走
    那么系统应按移动距离交替播放空间化脚步声
    当玩家停止移动
    那么系统不应继续循环播放脚步声

  场景: 无效射击不产生真实射击反馈
    假如训练步枪未形成双手持枪、跟踪无效、禁射或没有弹药
    当玩家按动右手 Trigger
    那么系统不得播放击发声、弹丸破空声或命中声
    而且不得显示枪口焰、弹体、曳光、撞击火花或新增弹着点

  场景: 有效射击产生可控的步枪后坐力
    假如玩家以双手稳定据枪
    当玩家扣动扳机完成一次有效射击
    那么击发后一个渲染帧内枪体应向后运动并出现枪口上跳
    而且枪体应出现轻微横向偏转而不是每次完全相同的纯垂直跳动
    而且横向偏转应由本局固定种子和射击序号确定以保证测试可重复
    而且枪体应经过短暂阻尼回弹并在 0.45 秒内基本回稳

  场景: 据枪稳定度影响枪体晃动和后坐力控制
    假如测试使用相同的基础枪线和固定随机种子
    当分别以高稳定度双手据枪和低稳定度双手据枪完成射击
    那么低稳定度状态的枪线晃动偏移应更大
    而且低稳定度状态的枪体上跳或横向响应应更明显或回稳更慢
    但是弹着不得来自与玩家枪线无关的纯随机散布

  场景: 未回稳时再次射击沿用当前受力枪线
    假如玩家已完成一次有效射击而枪体尚未回稳
    当玩家再次扣动扳机
    那么第二发应使用当前受后坐力影响的枪口或瞄准线方向
    而且第二发的曳光、命中计算、射击结果和射校记录应使用同一枪线

  场景: VR 后坐力不强制晃动头显
    假如玩家正在真实 VR 或 XR Device Simulator 中射击
    当有效射击产生后坐力
    那么系统不应强制旋转或平移 HMD 相机
    而且支持触觉时后手应收到主要短脉冲、前手应收到较弱短脉冲
    而且不支持触觉时仍应正常完成枪体后坐力、命中和射校记录

  场景: 按按钮换弹和切换左右肩
    当玩家触发换弹输入
    那么武器应进入按钮换弹流程
    而且 HUD 弹药数据应从弹药服务刷新
    当玩家触发左右肩切换输入
    那么武器射击参考点应切换到另一侧
    而且 HUD 或操作提示应显示当前肩侧

  场景: 本轮 3 发完成后打开弹着分析
    假如玩家已完成本轮第 3 发有效射击
    当弹着记录写入完成
    那么系统应打开“本轮弹着分析”界面
    而且射击输入应临时禁用

  场景: 弹数为 0 时禁止继续射击
    假如本轮剩余弹数为 0
    当玩家继续扣动扳机
    那么系统不应生成新子弹
    而且弹着记录不应新增命中点
    而且不应产生新的曳光、后坐力或触觉反馈
```

## Unity 验收点

- P1 允许使用射线或简化弹道完成命中计算，但每次有效射击必须有从枪口发出的可见弹道或曳光表现；后续可替换为更完整的 `Firearm`/`Bullet` 实现。
- 弹着记录不应只由子弹碰撞决定，还应记录射击时刻的准星状态和当前归零偏移。
- 同一套拾枪、前后手选择、射击、换弹、左右肩切换和瞄准逻辑必须同时支持真实 XR 输入、XR Device Simulator 和无 VR 输入替身。
- 真实 VR 使用右手 Grip 选择后握把、左手 Grip 选择前握把、右手 Trigger 击发；动作必须来自可配置 Input Action，不得硬编码具体厂商设备 API。
- 枪械初始不绑定相机；右手近距拾取、左手前握把选择和放手状态必须由 XR Direct Interactor / XR Grab Interactable 或等效的可测试交互组件驱动。
- 真实 VR 中 HMD 相机是唯一视角权威，不做枪线吸附、FOV 缩放或后坐力相机抖动；玩家通过实际移动头部和枪体完成机瞄。
- 无 VR 设备时，Unity Editor Play Mode 中应能直接看到训练步枪、双手替身控制效果、ADS/机瞄视角、弹道和靶面命中反馈。
- 后坐力应表现为枪体的短促冲量和阻尼回正；真实 VR 中不得通过强制改写 HMD 姿态制造震动。
- 本发射击使用施加本发后坐力前采样的有效枪线；未回稳时的后续射击使用当前受力枪线。
- 后坐力横向变化和测试输入必须可由固定种子、射击序号与可注入姿态历史重复生成。
- P1 的命中权威仍为服务层接受的射线或简化枪线结果；移动弹体、曳光、枪口焰、火花和声音只表现该结果，不得再次独立判定命中。
- 虚拟手允许使用基础关节弯曲或预设握持姿势，不要求手臂 IK；抓取对齐只能发生在手部视觉层。
- 脚步反馈按玩家根节点的地面移动距离触发，必须有停止阈值，避免头显自然微动造成连续脚步。

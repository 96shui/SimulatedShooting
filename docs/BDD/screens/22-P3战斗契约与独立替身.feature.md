# 22 P3 战斗契约与独立替身

阶段：P3。来源：task001 契约冻结清单 C01–C16；补充页面12/14/15/17/18/19/20/21。此处区分契约 Fixture 验收与后续生产玩法验收。

```gherkin
# language: zh-CN
功能: P3 三线独立开发契约
  场景: 默认数据与不可变集合
    假如 UI 尚未收到 P3 Session
    当读取默认 DTO
    那么集合和字符串应安全为空且没有有效会话或胜利
    而且已发布集合不能被原始列表的后续修改改变

  场景: 单一共享契约
    当 UI、场景与玩法测试程序集分别引用公共契约
    那么应复用既有弹药、玩家、队伍、HUD 与随机种子类型
    而且公共契约不依赖 UI、XR 或具体场景程序集
    而且 P1/P2 枚举序号与默认值不变

  场景: 配置拒绝非法值
    假如战斗配置包含非有限数值、非正生命或非法步速
    当验证配置
    那么应返回 InvalidInput
    而且地图的空节点、重复ID、候选点容量不足或不可导航也应被报告

  场景: 固定种子与场景事实替身
    假如两次使用相同固定种子和相同输入序列
    当使用随机、时钟、命中、感知和导航替身
    那么输出序列应一致
    而且替身应记录原始会话和事件ID而不读取真实硬件

  场景: UI 假服务重放与错误
    假如 UI 只连接 FakeTrenchService 或 FakeUrbanService
    当注入准备、战斗、胜利、失败和重试快照
    那么查询与完整事件应暴露同一快照
    而且 Busy、NotFound、InvalidState 和存储失败可以明确注入
    而且重复相同快照不重复通知，旧会话或旧修订不能污染当前快照
    而且替身不得自动计算敌人AI或胜负

  场景: 空白场景独立消费与卸载
    假如没有加载 TrenchScene 或 UrbanScene
    当测试在空白场景挂接 UI 文本和角色门状态 Probe
    那么仅使用契约快照即可刷新文本、角色位置和门状态
    当卸载 Probe 并再次发布快照
    那么不再有任何 Probe 订阅或场景更新

  场景: P3 战斗与移动配置
    假如模式为 P3
    那么战斗配置应为单发、弹药30/120、生命100、换弹2秒
    而且敌人攻击默认伤害10、间隔1秒、范围30米、半视角60度
    而且站蹲卧步速为1.5/0.9/0.4米每秒，离散转向30度
    而且真实VR视角始终来自HMD，姿态命令不强改相机高度
    而且 P1/P2 仍固定卧姿并禁人工移动

  场景: 检查与终局规则
    假如堑壕玩家进入合法搜索节点范围
    那么该节点按ID只登记一次且无固定顺序
    假如城镇房门已开、玩家在检查区并确认、房间无活敌
    那么该房间才可完成检查，空房也需检查
    而且同一Tick先处理死亡再判断胜利，只发布一次终局

  场景: 只开放地图A与基础队形
    当查询 P3 可用地图和队友命令
    那么仅返回地图A且可用命令为空
    而且三人沿路径前后间距各1.5米，二号朝前三号朝后
    而且路径失败保持当前位置，不拉动玩家

  场景: 最近摘要保存失败可重试
    假如存储替身注入 PersistenceFailed
    当保存已完成任务的最近摘要
    那么返回失败且既有摘要不被覆盖
    当故障清除后重试
    那么按模式保存最新摘要而不建立完整历史档案
```

生产伤害/移动/搜索/终局逻辑由 task004/007/010 实现；task001 验证类型、配置、端口、脚本快照与独立消费。实机预算为目标72Hz、CPU/GPU各≤11ms、稳定战斗0B/frame、加载≤5s，设备与实测由节点D登记，不把配置当作性能通过。
